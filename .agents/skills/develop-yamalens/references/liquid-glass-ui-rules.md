# YamaLens Liquid Glass実装規則

この文書は、YamaLensのSwiftUI画面、ナビゲーション、操作部品、カメラオーバーレイを実装・レビューするときに使用する。見た目と操作の正本は `doc/YamaLens_UI設計書.md` とし、この文書ではiOS 26のLiquid Glassを実装へ落とし込む規則を定める。

## 基本方針

- Liquid GlassをYamaLensの標準デザイン言語として採用する。
- Liquid Glassは、コンテンツの上に浮くナビゲーションと操作のレイヤーに使用する。山名、天気、注意理由、取得日時などの情報そのものを装飾で読みにくくしない。
- SwiftUIの標準コンポーネントが提供するLiquid Glassを優先し、独自のガラス表現を再実装しない。
- ガラス効果の量ではなく、情報階層、操作の分かりやすさ、屋外での視認性を品質基準にする。
- AppleがiOS 26以降で外観を更新した場合は、固定した模倣表現より標準コンポーネントの適応を優先する。

## 標準コンポーネントを優先する

- ナビゲーションには `NavigationStack`、タブには `TabView`、検索には `.searchable`、画面操作には `toolbar`、選択肢には `Menu`、確認には標準のsheet・alert・confirmation dialogを使用する。
- 標準部品へ独自の半透明背景、ぼかし、境界線、影を重ねて、システムのLiquid Glassを二重に描画しない。
- 標準の戻る、閉じる、検索、タブ操作を独自部品へ置き換えない。YamaLens固有の意味がある操作だけを独自コンポーネントにする。
- コンテンツは可能な範囲でedge-to-edgeに配置し、システムのナビゲーション・タブ・スクロール端効果が機能する構成にする。

## YamaLensでの使い分け

| 対象 | 方針 |
| --- | --- |
| 下部タブ、ナビゲーション、ツールバー | SwiftUI標準部品のLiquid Glassを使用する |
| 検索、Menu、sheet、alert | 標準の表現と遷移を使用する |
| カメラ上部のパック・方位・精度表示 | 映像上に浮く機能レイヤーとして、読みやすい最小限のガラス表現を使用できる |
| ズーム切替、手動補正、検索への切替 | 関連操作を一つのまとまりとして配置し、必要なら一つのGlassコンテナへまとめる |
| 選択中の山のミニ情報カード | カメラ上の主要な操作面として使用できる。文字の背後には十分な分離を確保する |
| 山一覧、天気、施設、メモ、注意カード | 情報コンテンツとして扱い、すべてをガラス化しない。標準背景と明確な情報階層を優先する |
| 前日の気象サマリー | 現在・予報より下の補助情報とし、降水量を読める標準情報面にする。注意色やガラス装飾で安全判断を示唆しない |
| 「ここへ行く」の出発地選択 | 標準sheet、Form、Picker、Buttonを使う。長い駅名を狭いSegmented Controlへ詰め込まない |
| 山候補ラベル | 実景の判読を妨げない小さなオーバーレイとし、候補すべてへ強いガラス効果を付けない |

## 独自Liquid Glassの使用条件

- 標準部品では表現できない、コンテンツ上に浮く重要な操作に限り `glassEffect(_:in:)` を使用する。
- 既定は `.regular` とし、形状は部品の大きさと役割に合わせてCapsuleまたは角丸Rectangleを選ぶ。
- `.clear` は、写真・カメラなどのメディア上で、背後を暗くしなくても内容と操作文字のコントラストを維持でき、前景が太く明瞭な場合だけ使用する。
- 色付けは選択中または主要操作の強調へ限定する。すべての部品をフォレストグリーンへ着色しない。
- タップ可能な独自ガラス部品だけをインタラクティブにする。状態ラベルへ不要な反応を付けない。
- 近接する複数のガラス部品は `GlassEffectContainer` でまとめ、コンテナを画面全体へ乱立させない。
- ガラス同士を重ねない。効果の上へさらにmaterial、blur、opacity、shadowを重ねる場合は、必要性とアクセシビリティを確認する。
- 形状変化を伴う遷移は操作の連続性を説明できる場合だけ使用し、装飾目的のmorphingを追加しない。

## 色と情報表現

- フォレストグリーンは主要操作・選択状態、チャコールとオフホワイトは情報面に使用する。Glassの色付けだけでブランドを表現しない。
- 警告の黄・橙・赤を通常のガラス装飾に流用しない。警告にはアイコン、短い理由、日時、公式情報への導線を併記する。
- Liquid Glassの明暗適応を前提にしても、山名、風速、日没、精度、情報鮮度は常に読めるコントラストを確保する。
- カメラ映像上では背後が急変するため、重要な文字に適応的な背景または十分な分離を持たせる。細い文字や色だけの状態表示を使用しない。

## アクセシビリティと屋外利用

- 「透明度を下げる」「コントラストを上げる」「視差効果を減らす」の各設定で、意味、操作、読み上げ順が変わらないことを確認する。
- 標準部品による自動適応を優先し、独自部品でも透明度や動きが減ってなお操作可能にする。
- Dynamic Typeで文字が拡大した場合は、ガラス面を固定高にせず、折り返しまたは縦方向への拡張を許可する。
- タップ領域は44pt以上とし、透明な見た目より実際の操作範囲を優先する。
- カメラ画面は日なた、逆光、暗い稜線を想定して実機確認する。装飾と視認性が競合する場合は、背景をより不透明にして視認性を優先する。
- VoiceOverでは、材質や見た目ではなく「候補」「精度」「選択状態」「実行する操作」を読み上げる。

## 性能

- 同時表示する独自ガラス効果を最小限にし、スクロール行や多数の候補ラベルへ個別適用しない。
- 複数効果は必要な範囲で `GlassEffectContainer` にまとめる。
- カメラ画面ではLiquid Glass追加前後のフレーム落ち、発熱、電池消費をiPhone 15 Pro以降の実機とInstrumentsで確認する。
- 性能不足をアニメーション時間の短縮だけで隠さず、効果数、重なり、更新頻度を減らす。

## レビューと検証

- 標準SwiftUI部品で実現できるものを独自ガラス部品へ置き換えていないか。
- Liquid Glassがナビゲーション・操作レイヤーに限定され、コンテンツの主役を奪っていないか。
- 通常、スクロール中、選択中、sheet表示中、カメラ背景の明暗変化で文字が読めるか。
- Light／Dark、透明度を下げる、コントラストを上げる、視差効果を減らす、Dynamic Type拡大を確認したか。
- 警告、低精度、オフライン、古い情報が色や透明度だけで表現されていないか。
- カメラ画面の独自効果を実機で性能・視認性確認したか。シミュレーターだけで完了扱いにしない。
