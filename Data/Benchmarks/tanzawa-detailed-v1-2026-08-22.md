# 丹沢詳細地形パック v1 実測記録

## 実測環境

- 実施日: 2026-08-22
- MacBook Pro Mac16,8
- Apple M4 Pro、48GBメモリ
- macOS 26.6.1
- Xcode 26.6
- Python 3、Apple Compression framework（LZFSE）

## 入力と生成結果

| 項目 | 実測値 |
| --- | ---: |
| 取得計画 | 3,700タイル |
| 取得成功 | 1,464原本 |
| 提供範囲外 | 2,236URL |
| 生成地形 | 1,453タイル |
| 約4m | 1,122タイル |
| 約8m | 289タイル |
| 約62〜63m | 42タイル |
| `catalog.sqlite` | 602,112byte |
| `terrain.lzfse` | 59,406,809byte |
| 配布4ファイル合計 | 60,009,636byte |

DEM5AとDEM5Bが同一座標で重なる11原本は、優先順位に従って一つの約4mタイルへ統合した。DEM5Cは対象範囲で提供されていなかった。DEM10Bの提供範囲外3タイルは取得範囲の南西・南東端で、登録済み17座の山頂位置には重ならない。

## 欠損セル

| 解像度 | 全セル | 欠損セル | 欠損率 |
| --- | ---: | ---: | ---: |
| 約4m | 73,531,392 | 43,585 | 0.0593% |
| 約8m | 18,939,904 | 11,277 | 0.0595% |
| 約62m | 1,966,080 | 76,080 | 3.8696% |
| 約63m | 786,432 | 396,531 | 50.4215% |

約63mタイルの高い欠損率は、矩形取得範囲の海域・提供域外を含む外周タイルによる。アプリは詳細タイルから粗いタイルへ順に探索し、全解像度で欠損した地点を未取得として扱う。

## 整合性と処理時間

- SQLite `integrity_check`: `ok`
- 全1,453タイルのLZFSE展開とSHA-256検証: 成功
- 全95,223,808セルの一括展開走査: 2.36秒
- 詳細パック生成: 約134秒
- Ed25519署名生成と再検証: 成功

上記時間は開発用Macでの一回の参考値であり、iPhone上の性能保証ではない。アプリは全タイルを一括展開せず、必要地点を含むタイルだけを読み、直近8タイルをキャッシュする。

## 予測稜線の結合確認

- iPhone 15 Pro・iOS 26.5シミュレーターで、署名済み詳細パックの導入、固定位置からの予測稜線生成、画面描画、削除までのUIテストに成功した。
- カメラ開始から描画済みオーバーレイ検出までは約3秒だった。XCUITestの1秒間隔の待機判定を含む参考値であり、稜線計算単体のベンチマークではない。
- スクリーンショットで、欠損区間を補間せず分割した破線、候補ラベル背面への描画、暗い背景上での視認性を確認した。

この結果はシミュレーターでの結合確認であり、実機の処理時間、カメラ映像上の視認性、発熱を保証しない。

## 山頂座標との照合

正式DEMにより既存の丹沢中心6座の座標ずれを検出し、国土地理院の山岳標高一覧・地理院地図検索で修正した。修正後の登録標高と約4m DEM標高との差は次の範囲に収まった。

| 山 | 登録標高 | DEM標高 | 差 |
| --- | ---: | ---: | ---: |
| 蛭ヶ岳 | 1,673m | 1,671m | -2m |
| 丹沢山 | 1,567m | 1,566m | -1m |
| 塔ノ岳 | 1,491m | 1,490m | -1m |
| 檜洞丸 | 1,601m | 1,601m | 0m |
| 鍋割山 | 1,273m | 1,272m | -1m |
| 大山 | 1,252m | 1,248m | -4m |

粗地形を使用する周辺11座は、登録標高との差が-6〜-38mだった。約62m格子内の山頂位置と丸めの影響として現時点では許容し、現地候補の確定結果とは扱わない。
