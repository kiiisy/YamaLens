# YamaLens UI設計書

- 文書バージョン: 0.13
- 作成日: 2026-08-17
- 更新日: 2026-08-25
- 対象: iPhone 15 Pro／15 Pro Maxおよび後継Proモデル、iOS 26
- 初期対応エリア: 丹沢山地

## 1. UIの目的

YamaLensは、山を探す入口と、登山前に必要な情報を確認する入口の両方を持つ。

- **調べる**: 一覧・検索から、行きたい山の情報を開く。
- **見つける**: 山頂や稜線でカメラを向け、見えている山の候補を知る。
- **確認する**: 天気、日没、小屋、アクセス、公式情報、自分のメモを一画面で確認する。

YamaLensでは、判断に必要な周辺情報を短時間で整理して見せる。経路案内が必要なときは地図アプリを開く。

## 2. デザイン原則

1. **カメラを使わなくても完結する**: ホームは山一覧。検索・お気に入りから全機能へ到達できる。
2. **安全情報を先に見せる**: 天気、風、日没、情報の取得時刻を詳細画面上部へ置く。
3. **不確かな情報を断定しない**: カメラ結果は常に「候補」。古い気象・営業情報には取得時刻を付ける。
4. **圏外でも迷わせない**: オフライン中は利用可能な情報を表示し、更新できない理由を端的に伝える。
5. **山で見やすい**: 屋外での視認性、大きめのタップ領域、片手で届く主要操作を重視する。
6. **情報源へ戻れる**: 変動する情報には公式ページへの導線を用意する。
7. **Liquid Glassは操作へ使う**: iOS 26の標準デザインを採用し、ガラス表現はコンテンツ上に浮くナビゲーションと重要な操作へ限定する。

### 2.1 UIイメージ画像の扱い

`doc/ui_images/` の画像は、YamaLensのUIを作成・変更する前に確認する補助的な参考資料である。`doc/ui_images/26819/` は2026-08-19に合意したPoCとして、正本文書と矛盾しない範囲で画面構成、情報階層、色、余白の基準にする。

- 画像からは、山岳写真と情報の重なり方、屋外での視認性、情報密度、余白、画面全体の落ち着いた雰囲気などを参考にできる。
- PoCの画面構成や雰囲気は採用するが、アイコン、写真、数値、文言は完成素材ではない。標準部品、アクセシビリティ、実データの状態に合わせて調整する。
- 画像に描かれていても、正本文書にない機能や動作を要件として追加しない。画像と正本文書が異なる場合は、事前決定事項、要求仕様、基本設計、本文書の順で正本文書を優先する。
- 具体的なUI判断は、対象画面の目的、iOS 26の標準SwiftUI部品、Liquid Glass方針、アクセシビリティ、屋外での操作性から独立して導く。
- PoC内の写真はレイアウト参照に限定し、アプリへ転載しない。実装画像は自前撮影、商用利用可能なストック写真、または個別の再利用条件を確認したオープンライセンス素材を使い、作者、出典URL、ライセンス、取得日、加工有無を記録する。

## 3. ナビゲーション構成

下部タブは3つとする。

```text
ホーム（山一覧）     カメラ          記録
      │                │             │
      ├─ 検索           ├─ 山候補     ├─ お気に入り
      │                │             ├─ 最近見た山・登頂済み
      └───────────→ 山詳細 ←────────┴─ オフラインパック・設定
                           │
                メモ編集 / 公式情報 / 地図アプリ
```

| タブ | 目的 | 初期状態 |
| --- | --- | --- |
| ホーム | 山を一覧・検索から選ぶ | 気になった山、お気に入り、最近見た山、丹沢の代表的な山 |
| カメラ | 見えている山の候補を確認する | カメラプレビュー、候補、精度状態 |
| 記録 | 自分の保存情報と設定を管理する | お気に入り、登頂済み、最近見た山、丹沢パック |

設定、データ出典、権限説明は記録右上の設定ボタンから開く。

- タブは標準のTabViewを使い、視覚上はアイコンだけを表示する。アイコンは仮決定とし、VoiceOverでは「ホーム」「カメラ」「記録」を読み上げる。
- ホームの気になった山・お気に入り・最近見た山は少数の抜粋、記録は全件管理とし、同じ一覧を重複表示しない。
- 設定は記録からシートで開き、ドラッグインジケータと下方向スワイプで閉じられるようにする。設定トップに不要な戻るボタンを置かない。下層画面は標準の横スワイプによる戻り操作を維持する。
- 山カードから山詳細へは、選択したカードの写真を起点に詳細上部の写真へ広がるズーム遷移を使用する。戻る際も写真は元のカードへ連続的に戻し、カードと山詳細の山名・本文はクロスフェードする。文字や操作部品をカード比率へ圧縮しない。
- 山詳細は戻るボタンに加え、内容が先頭にある場合に写真アプリと同様の下方向ドラッグで縮小しながら閉じられるようにする。ドラッグ中は遷移元のホームを背後に表示し、詳細本体と固定ヘッダーを一枚の画面として同時に移動・縮小する。閉じた後にヘッダーだけを残したり、別方向へ退避させたりしない。
- ドラッグしていない通常状態では、山詳細の背景を上下のSafe Areaを含む画面全体へ表示し、遷移元のホームやタブバーを端から露出させない。
- 縦スクロール中や横方向の施設一覧操作を奪わず、「視差効果を減らす」が有効な場合は縮小表現を省略しても、戻るボタンと下方向ドラッグの意味を維持する。

## 3.1 YamaLensらしいビジュアル方針

YamaLensは「山の名前を当てる道具」だけではなく、登山前の判断材料と自分の記録を持ち歩くアプリである。カメラ画面も、機械的なAR表示ではなく、落ち着いた**登山ノート／フィールドガイド**の印象を目指す。

- 基調色は深いフォレストグリーン、岩肌を思わせるチャコール、紙のようなオフホワイト。警告だけに黄・橙を使う。
- 山のラベルは斜めの大きな札ではなく、丸みを抑えた小さな情報タグにする。
- タグは「山名」「標高」「距離」の3要素を短く整理し、視線を遮らない下寄りの配置を基本とする。
- 山頂へは細いガイド線ではなく、先端に小さな山型マーカーを置いた控えめなリーダー線で結ぶ。
- 選択中の山だけをアクセント色で強調し、他の候補はグレー寄りの控えめな表示にする。
- 下部には候補リストではなく、選択中の山の「ミニ情報カード」を表示する。タップすると天気・小屋・メモのある山詳細へ展開する。
- コンパスは装飾的な大型アイコンにせず、方位と精度を小さく表示するステータス部品にする。

この方針により、既存アプリの構図や部品を模倣せず、YamaLens固有の「情報を確認して次の行動へ進む」体験を作る。

## 3.2 Liquid Glass方針

YamaLensは、iOS 26のLiquid Glassを標準デザイン言語として採用する。ただし、画面全体やすべてのカードを半透明にするのではなく、山の写真・一覧・天気・メモ等の**コンテンツ層**と、その上に浮く**ナビゲーション／操作層**を分ける。

- `TabView`、`NavigationStack`、ツールバー、検索、Menu、sheet、alertなどSwiftUI標準コンポーネントのLiquid Glassを優先する。
- 下部タブ、カメラ上のズーム・手動補正、選択中候補のミニカードなど、コンテンツ上に浮く重要な操作へ使用する。
- 山一覧、天気、施設、メモ、注意カードなどの情報面を一律にガラス化しない。可読性と情報階層を優先する。
- ブランド色のフォレストグリーンは、主要操作または選択状態へ限定して使う。すべてのガラス部品を着色しない。
- 警告色はLiquid Glassの装飾に流用せず、注意理由、アイコン、日時、公式情報への導線と組み合わせる。
- カメラ映像上は背景の明暗が変化するため、文字のコントラストを常に確保する。必要な場合はガラスをより不透明にし、景色を透かすことより読みやすさを優先する。
- 「透明度を下げる」「コントラストを上げる」「視差効果を減らす」の設定に追従し、効果が弱まっても意味と操作を維持する。
- 独自のLiquid Glass部品は標準部品で表現できない重要操作に限定し、過剰な効果による描画負荷と視覚的ノイズを避ける。

具体的なSwiftUI API、独自部品、性能、レビューの規則は [Liquid Glass実装規則](../.agents/skills/develop-yamalens/references/liquid-glass-ui-rules.md) に従う。

## 4. 画面設計

### 4.1 ホーム（山一覧）

**目的**: もっとも確実な入口として、カメラを使わずに山を開けるようにする。

```text
┌──────────────────────────┐
│ YamaLens                    🔍 │
│                              │
│ 気になった山              すべて > │
│ ┌ [写真] 蛭ヶ岳   8月25日          ┐ │
│ └        稜線がきれいだった          ┘ │
│                              │
│ お気に入り                    │
│ ┌ 丹沢山       1,567m      ★ ┐ │
│ └ 蛭ヶ岳       1,673m      ★ ┘ │
│                              │
│ 最近見た山                    │
│ ┌ 大山         1,252m        ┐ │
│ └ 塔ノ岳       1,491m        ┘ │
│                              │
│ 今の時期の丹沢            すべて > │
│ [大山] [塔ノ岳] [丹沢山] [蛭ヶ岳] │
│                              │
│ 丹沢の山                すべて > │
│ [大山] [塔ノ岳] [丹沢山] [蛭ヶ岳] │
└──────────────────────────┘
  ホーム          カメラ          記録
```

- 右上の検索ボタンから専用の検索画面を開く。検索画面では入力欄を最初から操作可能にする。検索と設定のアイコンは視覚上コンパクトにしつつ、44pt以上のタップ領域を維持する。
- 「今の時期の丹沢」は同梱の軽量データにある固定の季節メタデータによる紹介とし、詳細パック、通信、現在地、天気に依存しない。登山の安全性や実行を推奨する表現を使わない。
- 中心期間の山を優先し、件数が不足する場合だけ前後の紹介期間から補う。同じ山域グループの山に偏らないようにし、最大4件を表示する。各カードには山名、標高、短い季節の紹介理由を表示する。
- 「この近くの山」は利用者が位置情報の利用を選んだ場合だけ表示し、初回起動で権限を要求しない。未許可時は用途を示す任意の導線を置く。季節紹介とは別のセクションとして扱う。
- 取得中は進行状態を示し、対応済みまたは同梱済みの基本情報を持つ山のうち150km以内を距離順で最大10件表示する。水平精度が25mを超え100m以内の場合は距離と順序が「目安」であることを文字でも示し、100mを超える場合は再取得を案内する。
- 近い山が0件の場合は、遠い丹沢の山を代替表示せず、「近い山は対応地域にありません」「現在は丹沢を中心に収録しています」と山名検索へのボタンを表示する。
- 位置情報が拒否・制限・取得失敗の場合も山一覧と検索を残し、設定を開く、検索する、再試行する、のうち状態に合う回復操作を表示する。現在地と位置履歴は保存しない。
- 「設定を開く」から位置情報を許可してアプリへ戻った場合は、権限を再確認して現在地を自動取得し、追加のタップなしで近い山を更新する。
- お気に入りが空の場合は「よく行く山を保存するとここに表示されます」と案内する。
- 「気になった山」は記録が1件以上あるときだけ、お気に入りの前に表示する。撮影日時の新しい順に最大3件を示し、同じ山を複数回記録できる。
- 各行は写真のサムネイル、山名、撮影日、任意メモの短い先頭部分で構成する。行を押すと記録詳細を開き、「すべて」は撮影日時順の記録一覧を開く。お気に入りの山一覧と混在させない。
- 山行中で位置情報が使える場合のみ、任意で「現在地から近い山」を追加表示する。
- 各行をタップすると山詳細を開く。カード内に情報を詰め込み過ぎない。

### 4.2 検索・絞り込み

**目的**: 名称が曖昧でも、山域や標高から目的の山を見つける。

- 検索対象: 山名、別名、山域、都道府県。
- 絞り込み: 山域、標高帯、お気に入り、オフライン保存済み。
- 結果行: 山名、標高、山域。位置情報許可時のみ距離・方角を補助表示する。
- 0件の場合は、検索語を変える案内と「丹沢の山を一覧で見る」導線を表示する。

### 4.3 カメラ（山候補）

**目的**: 目の前の山の候補を知り、詳細情報へ移動する。

```text
┌──────────────────────────┐
│ 丹沢パック使用中        北西  ● 精度 良好 │
│                              │
│                              │
│         カメラ映像             │
│                              │
│             ◇ 蛭ヶ岳           │
│                1,673m / 12.4km  │
│                              │
│                  [ 1× | 2× | 3× ] │
│                              │
│ ┌────────────────────────┐ │
│ │ 蛭ヶ岳  1,673m  北西 12.4km      │ │
│ │ 風 8m/s  日没 17:42       詳細 > │ │
│ └────────────────────────┘ │
│ [検索から選ぶ]                    │
└──────────────────────────┘
  ホーム          カメラ          記録
```

#### 表現方針

- 山頂マーカーと控えめなリーダー線で、カメラ映像上の山と情報タグを結ぶパノラマ型のAR表示とする。
- タグは山の輪郭を隠さないよう、山頂の上または横へ逃がす。近接する候補は高さをずらし、重なりを避ける。
- タグは「山名」「標高」「距離」を2行以内でまとめる。角丸を強くしすぎず、YamaLensのフィールドガイド調の見た目にする。
- 上位の有力候補だけを常時表示する。ほかの候補は下部シートから選べるようにし、ラベル過多を避ける。
- 候補は山頂方向をARKitのカメラ姿勢、内部行列、表示変換で画面座標へ投影し、現在の画角内にある場合だけ表示する。端末を山とは逆方向、上方向、下方向へ向けた場合は、画角外の候補をラベルと下部シートへ残さない。
- カメラ映像上のラベルは最大5件、下部の「この画角の候補」は最大10件とする。画角境界では3度の保持余白を既存候補だけに適用し、候補の頻繁な出入りを抑える。
- 補助表示として、導入済みDEMから計算した山稜線の予測線を表示・非表示できる。実景とのずれを視覚的に確認できるようにし、実景や確定境界ではないことが分かる破線で表示する。詳細パック未導入・高度不明・DEM欠損等で生成できない場合は、推測線を表示せず理由を示す。

#### 手動補正

コンパス・GPSにはずれが生じるため、センサーだけに依存しない。

- 初期位置は端末センサーで自動的に合わせる。
- 下部候補トレイの「方位を調整」から補正モードへ入り、補正モード中だけ画面の横ドラッグを有効にする。
- ユーザーは画面を横方向へドラッグして、山稜線・ラベルを実景に重ねるように微調整できる。
- 補正中は「手動調整中」と表示し、補正量を「東へ4°」「西へ3°」のように示す。
- ドラッグの代替として、44pt以上の「西へ1°」「東へ1°」ボタンを下部に置く。タップでは1°、長押し中は1°刻みで連続補正し、指を離した時点で停止する。
- 「自動に戻す」ボタンでセンサー基準の位置へ戻せる。
- 補正値はカメラセッション中だけ有効とする。カメラ候補から山詳細を直接開いて戻る場合は保持し、ホームまたは記録へ離れた場合は破棄する。別地点や次回の利用へ恒久保存しない。

- 画面上部にオフラインパック名と精度状態を常時表示する。
- 山名ラベルは画面端に重ならない位置へ配置し、最大表示数を制限する。
- ラベルをタップすると山詳細へ遷移する。
- カメラ候補から開いた山詳細を直接閉じた場合は、停止していたカメラセッションを再開して同じカメラ画面へ戻す。ホームまたは記録へ移動した後は自動再開せず、利用者の明示操作で開始する。
- 下部ミニ情報カードには選択中の候補の基本情報、風、日没を表示する。横スワイプまたはタップで別候補を選べる。
- 「検索から選ぶ」は常に表示する。
- 画面下部寄りに `1×`、`2×`、`3×` のズーム切替を置く。選択中倍率を明確に表示し、倍率変更中もラベルを一瞬隠さず再配置する。
- カメラや位置情報が未許可の場合は、プレビューの代わりに権限の用途と許可ボタン、検索導線を表示する。
- 方位または姿勢が利用困難な場合は古い候補を消し、「方位を再確認しています」と状態を示したうえで、「金属や磁石を端末から離し、端末をゆっくり上下左右に動かしてください」と復旧操作を案内する。センサーが有効値を再取得したら、ユーザー操作なしで候補表示へ復帰する。
- 現在地が60秒を超えて古くなった場合は古い位置で候補を表示せず、画面を開いたまま現在地を自動再取得し、取得後に候補表示へ復帰する。屋内・地下などで現在地を取得できない場合は、その可能性を示し、空が見える場所での再取得と検索導線を表示する。
- 手動補正を行う場合は「稜線とラベルを重ねるように左右へ動かしてください」と案内する。
- 映像・位置情報は端末内で処理される旨を、初回説明と設定画面で示す。

#### 気になった山の記録

- AR候補を選択した状態でだけ、カメラ上の44pt以上の「記録する」操作を有効にする。候補を選択していない場合は、候補または検索から山を選ぶ案内を表示する。
- お気に入りの切替、候補の表示、山詳細を開く操作では撮影しない。撮影は「記録する」から明示的に始める。
- 撮影後は標準sheetで写真、山名、「AR候補として選択」、撮影日時を確認し、任意メモを入力できる。候補を確実な同定結果として表現しない。
- sheetには既定OFFの「正確な視点位置を端末内に保存」Toggleを置く。説明で座標と精度が端末内へ保存されることを示し、位置の取得・精度が不十分な場合も写真とメモだけで保存できるようにする。
- 「保存」は写真、選択した山、撮影日時、任意メモと、明示保存時だけの視点位置をアプリ専用領域へ保存する。成功時は短い成功表示だけを出してカメラ画面に留まり、ホームへ強制遷移しない。
- 保存失敗時は入力を保持し、空き容量の確認または再試行を案内する。写真ライブラリへの自動保存、共有、通常ログ・診断ログへの写真または視点位置の混入は行わない。

### 4.4 山詳細ダッシュボード

**目的**: 登山前・山行中に必要な情報を、鮮度と重要度順で確認する。

```text
┌──────────────────────────┐
│ ‹ 戻る       丹沢山             ☆ │
│ 1,567m   南西 4.2km              │
│                              │
│ ┌ 登山前チェック ────────────┐ │
│ │ 風: 北西 12m/s     注意         │ │
│ │ 日没: 17:42  （あと 2時間）      │ │
│ │ 天気取得: 10分前          詳細 > │ │
│ └────────────────────────┘ │
│                              │
│ ┌ 山頂付近の天気 ────── 詳しく見る > │
│ │ ☁ 8℃   北西 9m/s   降水 20%    │ │
│ │ 12時 8℃ / 15時 6℃ / 18時 5℃   │ │
│ │ 強い風の予報・取得 10分前        │ │
│ └──────────────────────┘ │
│                              │
│ 日の出 5:07        日の入り 18:20   │
│                              │
│ 山小屋                            │
│ ┌ 尊仏山荘 ───────── 公式 ↗ ┐ │
│ │ 提供元・確認日・短い補足          │ │
│ └──────────────────────┘ │
│ 登山口・交通                       │
│ [大倉登山口] [大倉バス停] [駐車場]   │
│                              │
│ 自分のメモ                     編集 > │
│ [登山口までの経路を開く]              │
│ 公式情報・データ出典              > │
└──────────────────────────┘
```

#### 表示順

1. 山名、標高、距離・方角、お気に入り。
2. 登山前チェックカード: 強風、雷・警報、日没までの時間、情報鮮度。
3. 現在の天気と直近予報の概要カード。押下すると時間別予報、注意情報、前日の気象サマリー、日照、提供元をまとめた天気詳細を開く。
4. 山頂座標における当日の日の出・日の入り。
5. 山小屋。
6. 複数の登山口。各登山口からアクセス、駐車場・交通、立ち寄り検索を開く。
7. 自分のメモ・確認リスト。
8. 地図アプリでのアクセス検索、外部登山サービス、公式情報への導線。

- 日の出・日の入りは端末内で計算し、「山頂座標・今日」を明示する。周辺地形による遮りや現地の明るさを反映した時刻とは表現しない。
- 山詳細の大見出しは「山小屋」と「登山口」に限定する。山小屋は山に直接紐付け、登山口は複数を同格に表示する。複数件は2列のコンパクトなカードとして横並びにし、各カードを44pt以上のタップ領域にする。山小屋を登山口へ一意に従属させない。
- 登山口の行を押すと標準sheetを開き、その登山口に明示的に紐付くバス・ケーブルカー・駐車場と、地図アプリで経路を開く導線を表示する。交通や駐車場を山詳細の独立カテゴリへ分割しない。sheetの先頭で「公共交通」「車」を選び、公共交通ではバス・ケーブルカー、車では駐車場だけを表示する。
- バス停・ケーブルカー・駐車場の「地図を開く」では「ここへ行く」画面を開き、目的地と出発地を確認してから地図アプリを開けるようにする。この画面に移動手段の選択は置かず、登山口sheetで選択済みの「公共交通」または「車」をそのまま地図アプリへ渡す。
- 「ここへ行く」画面では「現在地」「よく使う出発駅」を選び、「地図アプリで経路を検索」で設定済み地図アプリを開く。登録駅がない場合は設定への登録導線を表示し、地図アプリ設定が「毎回選択」の場合だけ実行ボタンの後に地図アプリ選択を表示する。
- 登山口sheetには、当該登山口へ明示的に紐付く代表的な温泉と、「登山口周辺」「最寄り駅周辺」などの立ち寄り地点を表示する。登録済み温泉は公式ページと取得日時付きで確認でき、コンビニ、食事、追加の温泉候補は地図アプリで検索できるようにする。周辺店舗を網羅した一覧や営業中かどうかをYamaLens内へ表示しない。
- 立ち寄り検索は「駅名（登山口名）＋カテゴリ」の1本の文字列を渡さず、カテゴリと検索地点を中心にした地図範囲を別々に渡す。中心地点を解決できない場合は、カテゴリだけを渡すことを明示する。
- 山小屋の行を押すと標準sheetを開き、種別、短い説明、提供元、最終確認日または取得日時、HTTPSの公式ページへの導線を確認できるようにする。
- 山詳細の最上部は既定の山イラストを表示する。画像右下の44pt以上のラベル付き写真操作から、利用者が選んだ写真へ変更できる。写真操作は上部の戻る・お気に入り・共有と重ならない位置に置き、画像の縦横比が異なっても位置を動かさない。写真未設定時は既定イラストへ戻し、設定した写真はこのiPhone内だけに保存する。選択写真はホーム等の山カードにも反映し、カードから詳細への遷移では同じ写真を連続して表示する。
- 山ノートの「行く前」「山行中」「行ったあと」はそれぞれ直接入力を開く44pt以上の操作とする。「山ノートを開く」ボタンは置かない。各操作を長押しすると、保存済み内容または未入力状態をプレビューする。
- 検証済みYAMAP山ページがある場合、施設情報の後に「外部サービス」として「YAMAPで見る」を1行表示する。補足に「山ページから登山計画を作成できます」と示すが、ボタン押下だけで計画が作成されるとは表現しない。インストール済みならアプリ、未導入ならWebで開くことをVoiceOverのヒントで伝え、外部サービスの情報・計画はYamaLensの安全判断ではない旨を併記する。URL未登録時は空のセクションを表示しない。ヤマレコはMVPでは表示しない。
- sheetは主要情報と公式導線が見える約7割の高さから表示し、上方向への展開、下方向のスワイプ、「閉じる」のいずれでも操作できる。山詳細のスクロール位置を保持する。
- 営業時間、料金、運行状況等の変動値は、人が確認したデータまたは承認済みの公式情報源から検証済みとして取得したデータだけを、最終確認日または取得日時とともに表示する。古い情報・更新失敗を現在の状態として見せず、公式ページへ誘導する。施設未整備の山では架空の行を表示せず、理由が分かる空状態を表示する。

#### 天気概要と詳細

- 山詳細には、現在の天気、気温、風、取得可能な直近の降水確率、直近3時間、最も重要な注意理由、取得日時を一つの概要カードとして表示する。すべての時間別値や前日サマリーを山詳細へ展開しない。
- 概要カード全体を44pt以上のタップ領域とし、「詳しく見る」とシェブロンを併記する。VoiceOverでは時間別予報と前日サマリーを開く操作であることを読み上げる。
- 概要カードを押すと大きなsheetで天気詳細を開く。sheetは下方向のスワイプと「閉じる」の両方で戻れ、山詳細の閲覧位置を保持する。
- 天気詳細には、対象の山名・標高・山頂付近であること、手動更新、現在値、時間別予報、注意情報、前日の気象サマリー、鮮度、WeatherKit取得日時、提供元・法的情報を表示する。複数ユーザー向け共有キャッシュへ移行した場合は、必要に応じて共有キャッシュの公開日時も詳細に表示する。
- 手動更新は、その時点で利用可能な最新情報を確認する操作とする。個人利用MVPではWeatherKit更新を試し、将来の共有キャッシュ利用時は配信済み最新版を確認する。操作のたびにWeatherKitが新しい予報を生成・取得するとは表現しない。
- 将来の日別予報は、取得済みの実データがある場合だけ天気詳細へ追加する。未実装・未取得の値を固定値や推測値で補わない。日の出・日の入りは気象データと分離し、山詳細で端末計算値を表示する。

#### 注意カード

- 通常: 落ち着いた背景で「情報は◯分前に更新」と表示。
- 注意: 風、雷、警報、日没が近い等で強調色とアイコンを使用する。
- 気象は取得後1時間以内を「最新」、1時間超3時間以内を「更新を推奨」、3時間超を「古い情報」と表示する。
- WeatherKitの現在から12時間以内の予報風速10m/s以上は「風が強い予報」、15m/s以上は一段強い注意として、値と対象時間を併記する。これらを登山可否の文言へ変換しない。
- 現在から12時間以内の雷、雪・みぞれ・着氷性降水、任意の3時間区間で5℃以上の気温低下は、取得できた場合だけ事実と対象時間を表示する。未取得を「なし」と表示しない。
- 公式警報は発表機関名と詳細リンクを表示し、WeatherKitから提供された意味を変更しない。
- 緊急性を示す色だけに依存せず、短いテキストで理由を必ず併記する。
- 「登山可／不可」は表示しない。代わりに公式情報への導線を置く。

#### 前日の気象サマリー

- 現在・これからの予報の直後に「前日の気象サマリー（山頂付近）」を置く。現在予報より強く見せないが、降水量は折りたたまず最初の行で確認できるようにする。
- 最初の行には対象日、降水量、取得できる場合は最高／最低気温を表示し、詳細で降雪量、対象地点、提供元、取得日時を確認できるようにする。
- 「前日は雨」「前日の降水量 12mm」のように取得値を事実として示し、「登山道がぬかるんでいます」「登山に適しません」等へ変換しない。
- 値が欠ける場合は項目ごとに「未取得」、全体を取得できない場合は「前日の情報を取得できません」と表示する。0mm・0cmはWeatherKitが0として返した場合だけ表示する。
- 前日サマリーだけ更新に失敗した場合、現在・予報カードをエラー表示へ変えない。前日部分に再試行と取得日時を表示する。

#### 登山前チェック（将来拡張）

山詳細の最上部に、展開可能な確認カードとして表示する。

```text
登山前チェック                         4 / 6
✓ 丹沢オフラインパック       保存済み
✓ 天気                         20分前に更新
! 風                           山頂付近 12m/s
✓ 日没                         17:42
○ 山小屋                       公式情報を確認する
○ 登山口へのアクセス           地図アプリで確認する
```

- `✓` は確認済み、`!` は注意、`○` は未確認を表す。情報がない項目は「未確認」と明示する。
- 地図アプリ・公式サイトを開く操作から戻った後、ユーザーが確認済みにできる。
- 色だけで状態を示さず、アイコンとテキストを併用する。
- 登山可否を示すスコアや判定は表示しない。

#### 登山口アクセスsheet

- 山詳細には複数の登山口を同格の2列カードとして表示する。各カードには、紐付く駐車場・バス停・ケーブルカーの種別を短く表示する。
- 登山口カードを押すと、その登山口専用のアクセスsheetを開く。駐車場、最寄り駅・バス停など、当該登山口に明示的に紐付く施設だけを表示する。
- 各目的地の「地図を開く」をタップすると「ここへ行く」sheetを開く。目的地と出発地、実行ボタンを表示するが、アクセスsheetで選択済みの移動手段は表示・再選択させない。
- 出発地は「現在地」「よく使う出発駅」の選択行とする。駅名が長くDynamic Typeが大きい場合にも対応するため、狭いSegmented Controlへ詰め込まない。
- 「現在地」はYamaLensの位置情報権限に依存せず、地図アプリ側の現在地を使用する。よく使う出発駅が未登録の場合は「よく使う出発駅を登録」を表示する。
- 標準はAppleマップとし、Google Mapsがインストールされている場合だけ選べる。
- YamaLens内では道順を表示しない。地図・ナビゲーションは選択した地図アプリへ委ねる。
- 圏外時は「地図アプリで経路を取得できない場合があります」と表示し、目的地・登録駅の名称と公式アクセス情報は閲覧可能にする。

- アクセス手段の選択部品、各「地図を開く」Button、「ここへ行く」sheetの出発地選択行と実行ボタンは44pt以上にする。
- VoiceOverでは、目的地、選択中の出発地、登山口で選択済みのアクセス手段を使用すること、外部地図アプリを開くことを読み上げる。

### 4.5 山小屋・登山口の詳細

**目的**: ダッシュボードでは収まらない情報を、種別ごとに確認する。

- 施設の詳細sheetでは、短い説明の後に、営業期間、予約、収容人数、料金、営業時間、休業日、アクセス、運行主体等のうち確認済みの項目だけをラベルと値の組で表示する。未確認項目の空行や推測値は表示せず、属性がない場合も概要、最終確認日、提供元、公式ページは確認できるようにする。
- リストの1行には名称と最終確認日または取得日時を表示する。短い説明と提供元は、行を押して開くsheetへ置く。
- 営業情報や運行情報など変動する内容には「公式情報を確認」リンクを優先して置く。
- 外部サイトを開く直前に、対象となる運営者名と、選択中のブラウザで開くことを分かるようにする。Safariは個別指定せず、既定のブラウザとして扱う。
- 山詳細の行から標準sheetを開き、情報を段階的に表示する。初期画面へ説明文や出典をすべて展開しない。
- 山詳細の大見出しは山小屋と登山口に限定する。交通、駐車場、代表的な温泉は対応する登山口のsheet内へ置き、コンビニ・食事・追加の温泉候補は登山口または最寄り駅周辺を検索するメニューへ置く。

### 4.6 メモ編集

- 「行く前」「山行中」「行ったあと」に分けた自由記述メモ、行きたい時期、確認リスト、お気に入り、手動の登頂済み状態を編集する。
- 登頂済みは利用者が明示的に切り替える記録であり、GPS活動記録や登頂の自動判定を行わない。
- 保存は明示ボタンとし、未保存変更がある状態で戻る場合は確認する。
- メモは端末内保存であることを画面下部に表示する。

### 4.6.1 気になった山の記録一覧・詳細

- 一覧は撮影日時の新しい順に、写真のサムネイル、山名、撮影日、任意メモの先頭部分を表示する。記録がない場合は空の一覧をホームに表示せず、カメラで候補を選んで記録する案内だけを示す。
- 詳細では写真、山名、撮影日時、任意メモ、「AR候補として選択した記録」である説明を表示する。正確な視点位置を保存した記録だけ、その事実と精度を表示する。地図、共有、写真ライブラリ保存はMVPでは表示しない。
- メモは詳細から編集できる。削除は標準の確認ダイアログで、写真と保存済みの視点位置も削除されることを明記する。
- すべての行、保存、削除、位置保存Toggleは44pt以上の操作領域を持つ。VoiceOverでは山名、撮影日、メモの有無、視点位置を保存したかを読み上げる。

### 4.7 記録／オフラインパック管理

```text
┌──────────────────────────┐
│ オフラインパック             管理 │
│                              │
│ オフラインパック                │
│ ┌────────────────────────┐ │
│ │ 丹沢山地                     保存済み │ │
│ │ 218 MB / 更新: 2026-08-17       > │ │
│ └────────────────────────┘ │
│ 気になった山                  3件 > │
│ お気に入り                    4件 > │
│ 最近見た山                    6件 > │
│                              │
└──────────────────────────┘
```

- オフラインで使える山域、容量、最終更新日を一目で示す。
- 個人利用MVPではCloudflare R2の静的HTTPS配信から丹沢詳細パックを導入・更新・削除できる。更新確認で新しい版がない時は再ダウンロードしない。通信不可時は「通信なし。保存済み情報を表示中」と示す。配布URLやR2の名称は通常画面に表示しない。
- 内蔵基本データは「丹沢の山」と「周辺候補」の件数を分けて示す。周辺候補は富士山等をARで見分けるための補助データであり、丹沢以外のパックを保存済みとは表現しない。
- MVPでは丹沢パックだけを表示する。奥多摩、富士山、八ヶ岳などMVP後の山域を保存候補として表示しない。
- 自動保存、Wi-Fi・モバイル通信の切替、近隣山域の提案は個人利用MVP後の機能とし、MVPの設定画面には表示しない。
- 更新中は進捗・残り容量を表示し、完了前の旧パックを保持する。
- 削除操作は確認ダイアログを出し、個人メモ、お気に入り、気になった山の記録と写真は削除しないことを明示する。

### 4.8 初回説明・権限

初回起動は、説明を3画面以内に収める。

1. 「山を調べる。見えている山を知る。」
2. 「丹沢パックを保存すれば、圏外でも山候補を表示できます。」
3. 「カメラ・位置情報は山候補表示に使います。気になった山を記録する時だけ写真を端末内へ保存でき、正確な位置は選んだ時だけ保存します。」

権限は機能を使う直前に要求し、拒否時は検索・一覧の代替導線を提示する。

**目的**: 通信量、端末容量、権限、データの鮮度をユーザーが自分で管理できるようにする。設定項目を増やし過ぎず、通常の利用で変更するものに限定する。

│                              │

│ 位置情報                  使用中のみ > │
│                              │

│                              │
│ データ・プライバシー                │

│ プライバシー                       > │

│                              │

#### オフラインパック設定

- **保存済みパックを管理**: 個人利用MVPでは丹沢パックだけについて、追加、更新、削除、容量、最終更新日を確認できる。削除してもメモ・お気に入り・気になった山の記録と写真は残ることを明示する。更新は通信可能時にだけ有効にする。
- 自動ダウンロード、Wi-Fi接続時のみ、モバイル通信、保存容量上限はMVP後に追加する。追加時は自動ダウンロードを初期値オフ、Wi-Fi接続時のみを初期値オン、モバイル通信を初期値オフとする。
- 開発ビルドでARテストパックを表示する場合は「ARテスト用・詳細情報なし」と明記し、正式対応パックと同じ保存済み状態・対応地域表示を使わない。複数の現地検証パックは一式として保存・削除できるようにし、カメラ画面では現在地から自動選択した地形パック名を候補表示を妨げない小さな補助表示で示す。

#### カメラ・位置情報設定

- 権限の現在状態を表示し、変更が必要な場合はiOSの設定画面へ遷移する。
- AR表示の手動補正はカメラ画面のセッション内操作で完結し、設定画面には置かない。
- ラベルの表示数やズーム倍率など、検証段階で必要な詳細設定は開発者用画面に限定し、通常の設定画面には出さない。

#### アクセス設定

- SwiftUI標準の `Form` を使い、「よく使う出発駅」を1件だけ登録・変更・削除できるようにする。
- JR・私鉄・地下鉄を含む、地図アプリで検索できる正式名称を利用者が直接入力する。例として `JR新宿駅` を示し、入力した名称を外部地図の出発地検索語として使うことを明示する。YamaLensは鉄道会社・路線の正しさを判定・補完しない。
- 入力した駅名は前後の空白を除去して端末内へ保存する。入力・変更・削除に通信は必要ない。
- 登録駅の利用にYamaLensの位置情報権限は不要であり、登録駅名以外の検索履歴は保存しないことをプライバシー説明へ記載する。
- 「地図アプリ」ではAppleマップ（既定）、Google Maps（端末にインストールされている場合だけ）、毎回選択を標準の選択行で設定できる。Google Mapsが利用できない状態で選択済みだった場合は、Appleマップで開く。
- 「公式サイトを開くブラウザ」では既定のブラウザ（既定）、Chrome（端末にインストールされている場合だけ）、毎回選択を標準の選択行で設定できる。Chromeが利用できない状態で選択済みだった場合は、既定のブラウザで開く。

#### データ・プライバシー

- 気象、地形、施設などの出典・利用条件を確認できる。
- WeatherKitの帰属表示と法的リンク、国土地理院データの出典と加工表示を確認できる。
- カメラ映像、気になった山の写真、位置情報、個人メモ、よく使う出発駅の端末内処理方針を簡潔に表示する。気になった山の正確な視点位置は記録ごとの明示保存時だけ保持すること、登録駅名以外の検索履歴を保存しないことも明示する。
- 開発モード時だけ表示する診断ログ画面では、保存件数、各ログの保存日・削除予定日・保持指定を確認し、個別削除と全削除を行える。通常利用では記録を開始しない。
- Debugビルドのカメラ画面には小さな「診断記録」Menuを表示する。「観測ログのみ」を既定にし、「映像を添付（最大30秒）」は利用者が明示して選ぶ項目にする。添付映像は音声なしで、記録開始後だけを保存する。開始後は赤い記録状態、サンプル数、問題マーカー、目視で確認した山、保存、破棄を表示する。映像を選んだ場合は「準備中」「添付中」「上限到達」を文字でも表示し、映像の開始または保存に失敗した場合は、観測ログだけを保存したことを明示する。保存と破棄は片手で届く操作面に置き、破棄は確認を挟む。
- 診断ログ詳細では、記録時のラベルを橙、現在の候補計算を緑として同じ疑似画角へ重ね、スライダー、前後ボタン、自動再生でサンプルを移動できるようにする。現在の計算は保存済み5Hzサンプルを先頭から処理し、安定化状態を含めて再計算する。両方に存在する候補は平均・最大の画面位置差を表示し、問題マーカーから該当時刻へ移動できるようにする。明示的に添付した映像がある場合は、生のカメラ映像を標準プレーヤーで別に再生し、候補リプレイや診断UIを焼き込んだ映像ではないことを示す。正確な座標は開発画面内だけに表示する。
- 診断ログ詳細の共有メニューでは「匿名化サマリー」を既定とする。サマリーには記録時間、端末情報、精度の範囲、候補の山IDだけを含め、正確な位置と記録時刻、添付映像は含めない。正確な座標を含むリプレイ用または添付映像を共有する場合は、含まれる項目をプレビューし、「正確な位置を含めて共有」の追加確認を行う。共有用の一時ファイルは、共有完了またはキャンセル時に削除する。
- AI機能を将来有効化した場合のみ、AIへの送信内容・利用上限・オン／オフをこの画面に追加する。

#### 危険な操作

- パック削除、全キャッシュ削除、メモの全削除は確認ダイアログを必須とする。
- メモ全削除はオフラインパック削除とは別の操作にし、初期画面には置かない。

### 4.10 将来拡張: 登山予定日の前日通知

- 登山予定日を登録した画面に「前日に通知」Toggleを置き、既定はOFFとする。通常の初回説明やアプリ初回起動では通知権限を求めない。
- 最初にToggleをONにした直後、前日確認を促す用途と、通知が最新気象や安全を保証しないことを説明してからシステム権限を要求する。
- 初期通知時刻は前日18時とし、予定ごとに変更できる。権限拒否時はToggleを有効に見せず、「iOSの設定を開く」と通知なしで前日確認を使えることを示す。
- 通知をタップすると対象の山詳細へ移動し、通信可能なら気象更新を試す。本文は既定で山名や気象値をロック画面へ露出させず、「予定している山の情報を確認してください」とする。
- 通知は配信保証、緊急警報、気象警報の代替として表現しない。

## 6. 色・文字・アクセシビリティ

- ベースは白または濃色のどちらでも視認性を確保し、屋外での高コントラストを優先する。
- 標準状態は自然を想起する深い緑または青緑をアクセントに使う。警告は黄・橙・赤を意味づけとテキストで併用する。
- 本文はDynamic Type対応。重要な数値（風速、日没までの時間など）は本文より大きく表示する。
- タップ領域は原則44pt以上とする。
- アイコンだけで状態を伝えず、VoiceOver用のラベルを付与する。
- カメラ画面ではラベルに背景・影を付け、明暗のある山景色でも読めるようにする。
- Liquid Glassは「透明度を下げる」「コントラストを上げる」「視差効果を減らす」で意味と操作を失わないようにする。

## 7. 主な状態別の表示

| 状態 | UIの扱い |
| --- | --- |
| 圏外 | 上部に「通信なし」。気象等は最終取得時刻付きで表示し、更新ボタンは無効化する。 |
| 丹沢パック未保存 | カメラ画面に「オフライン用の丹沢パックを保存してください」と表示。通信可能なら保存画面へ誘導する。 |
| 位置・カメラ未許可 | 機能を使う目的と許可ボタン、検索へ戻るボタンを提示する。 |
| 方位精度が低い | 古い候補を消し、「方位を確認中」と磁石・金属から離れる案内を明示する。有効値の再取得後は自動復帰する。 |
| データが古い | 数値の近くに最終取得時刻を置き、公式サイトへの導線を強調する。 |
| 情報なし | 「未確認」と表示し、推測値・空のカードで埋めない。 |
| 前日気象だけ取得失敗 | 現在・予報は通常表示し、前日の領域だけ「取得できません」と再試行を表示する。 |
| 共有キャッシュが古い・更新失敗 | 直前の正常値をWeatherKit取得日時付きで表示し、「古い情報」または「更新を確認できません」と示す。端末の再試行で必ずWeatherKitが更新されるとは表現しない。 |
| 出発駅未登録 | 「ここへ行く」で現在地を選択でき、登録駅の位置に「よく使う出発駅を登録」を表示する。 |
| 出発駅名が空 | 保存を無効にし、JR・私鉄・地下鉄を含む正式名称を入力する案内を表示する。 |
| 気になった山の写真保存に失敗 | 撮影後の確認sheetを閉じず、入力したメモを保持する。空き容量の確認または再試行を案内する。 |
| 気になった山の視点位置を取得できない | 位置を保存しないことを明示し、写真とメモだけで記録できる。 |
| 今の時期の丹沢に該当山がない | 空白のカードを置かず、山名検索への導線を表示する。 |
| 近い山が0件 | 「近い山は対応地域にありません。現在は丹沢を中心に収録しています」と、山名検索のボタンを表示する。 |

## 8. UI受け入れ条件

1. 初めて使うユーザーが、ホームから検索して任意の山の詳細を開ける。
2. 位置情報やカメラを許可しなくても、一覧、検索、山詳細、メモを利用できる。
3. カメラ画面で、オフライン中であること・使用中の山域パック・候補精度を確認できる。
4. 山詳細の最初の画面内で、風、日没、天気取得時刻、公式情報への導線を確認できる。
5. 変動する情報には、少なくとも取得時刻または最終確認日が表示される。
6. 未許可・圏外・パック未保存・精度低下の各状態で、ユーザーが次に取るべき操作を一つ理解できる。
7. 主要な操作は片手で届く下部領域または下部タブから行える。
8. Liquid Glassがナビゲーションと重要な操作に限定され、情報コンテンツの可読性を妨げない。
9. Light／Dark、透明度を下げる、コントラストを上げる、視差効果を減らす、Dynamic Type拡大でも主要情報と操作を認識できる。
10. 開発モードの診断ログは記録開始前に保存されず、保存日・削除予定・保持指定を確認して個別または全件削除できる。
11. 正確な位置を含む診断ログを共有する場合、共有内容のプレビューと追加確認が表示される。
12. 前日の気象サマリーは現在・予報と区別され、降水量、対象日、提供元、取得日時または未取得状態を確認できる。
13. 登山口アクセスで確定した目的地・移動手段を再選択せず、現在地または登録駅から外部地図を開ける。位置情報を拒否していても登録駅を利用できる。
14. AR候補を選んだ後だけ、利用者が明示的な撮影・保存操作で「気になった山」を記録できる。ホームには最新の記録が表示され、お気に入りとは別に閲覧・削除できる。
15. 詳細パック未導入、通信なし、位置情報未許可のいずれでも、ホームに同梱データから「今の時期の丹沢」が表示される。近い山が0件の場合は、理由と山名検索への導線が表示される。
