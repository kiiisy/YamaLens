# YamaLens UI設計書

- 文書バージョン: 0.13
- 作成日: 2026-08-17
- 更新日: 2026-08-21
- 対象: iPhone 15 Pro／15 Pro Maxおよび後継Proモデル、iOS 26
- 初期対応エリア: 丹沢山地

## 1. UIの目的

YamaLensは、山を探す入口と、登山前に必要な情報を確認する入口の両方を持つ。

- **調べる**: 一覧・検索から、行きたい山の情報を開く。
- **見つける**: 山頂や稜線でカメラを向け、見えている山の候補を知る。
- **確認する**: 天気、日没、小屋、アクセス、公式情報、自分のメモを一画面で確認する。

YamaLensでは、判断に必要な周辺情報を短時間で整理して見せる。経路案内が必要なときは地図アプリを開く。

## 2. デザイン原則

1. **カメラを使わなくても完結する**: ホームは山一覧。検索・お気に入りから全機能へ到達できる。
2. **安全情報を先に見せる**: 天気、風、日没、情報の取得時刻を詳細画面上部へ置く。
3. **不確かな情報を断定しない**: カメラ結果は常に「候補」。古い気象・営業情報には取得時刻を付ける。
4. **圏外でも迷わせない**: オフライン中は利用可能な情報を表示し、更新できない理由を端的に伝える。
5. **山で見やすい**: 屋外での視認性、大きめのタップ領域、片手で届く主要操作を重視する。
6. **情報源へ戻れる**: 変動する情報には公式ページへの導線を用意する。
7. **Liquid Glassは操作へ使う**: iOS 26の標準デザインを採用し、ガラス表現はコンテンツ上に浮くナビゲーションと重要な操作へ限定する。

### 2.1 UIイメージ画像の扱い

`doc/ui_images/` の画像は、YamaLensのUIを作成・変更する前に確認する補助的な参考資料である。`doc/ui_images/26819/` は2026-08-19に合意したPoCとして、正本文書と矛盾しない範囲で画面構成、情報階層、色、余白の基準にする。

- 画像からは、山岳写真と情報の重なり方、屋外での視認性、情報密度、余白、画面全体の落ち着いた雰囲気などを参考にできる。
- PoCの画面構成や雰囲気は採用するが、アイコン、写真、数値、文言は完成素材ではない。標準部品、アクセシビリティ、実データの状態に合わせて調整する。
- 画像に描かれていても、正本文書にない機能や動作を要件として追加しない。画像と正本文書が異なる場合は、事前決定事項、要求仕様、基本設計、本文書の順で正本文書を優先する。
- 具体的なUI判断は、対象画面の目的、iOS 26の標準SwiftUI部品、Liquid Glass方針、アクセシビリティ、屋外での操作性から独立して導く。
- PoC内の写真はレイアウト参照に限定し、アプリへ転載しない。実装画像は自前撮影、商用利用可能なストック写真、または個別の再利用条件を確認したオープンライセンス素材を使い、作者、出典URL、ライセンス、取得日、加工有無を記録する。

## 3. ナビゲーション構成

下部タブは3つとする。

```text
ホーム（山一覧）     カメラ          マイ
      │                │             │
      ├─ 検索           ├─ 山候補     ├─ お気に入り
      │                │             ├─ 最近見た山・登頂済み
      └───────────→ 山詳細 ←────────┴─ オフラインパック・設定
                           │
                メモ編集 / 公式情報 / 地図アプリ
```

| タブ | 目的 | 初期状態 |
| --- | --- | --- |
| ホーム | 山を一覧・検索から選ぶ | お気に入り、最近見た山、丹沢の代表的な山 |
| カメラ | 見えている山の候補を確認する | カメラプレビュー、候補、精度状態 |
| マイ | 自分の保存情報と設定を管理する | お気に入り、登頂済み、最近見た山、丹沢パック |

設定、データ出典、権限説明はマイ右上の設定ボタンから開く。

- タブは標準のTabViewを使い、視覚上はアイコンだけを表示する。アイコンは仮決定とし、VoiceOverでは「ホーム」「カメラ」「マイ」を読み上げる。
- ホームのお気に入りと最近見た山は少数の抜粋、マイは全件管理とし、同じ一覧を重複表示しない。
- 設定はマイからシートで開き、ドラッグインジケータと下方向スワイプで閉じられるようにする。設定トップに不要な戻るボタンを置かない。下層画面は標準の横スワイプによる戻り操作を維持する。
- 山カードから山詳細へは、選択したカードの写真を起点に詳細上部の写真へ広がるズーム遷移を使用する。戻る際も写真は元のカードへ連続的に戻し、カードと山詳細の山名・本文はクロスフェードする。文字や操作部品をカード比率へ圧縮しない。
- 山詳細は戻るボタンに加え、内容が先頭にある場合に写真アプリと同様の下方向ドラッグで縮小しながら閉じられるようにする。ドラッグ中は遷移元のホームを背後に表示し、詳細本体と固定ヘッダーを一枚の画面として同時に移動・縮小する。閉じた後にヘッダーだけを残したり、別方向へ退避させたりしない。
- 縦スクロール中や横方向の施設一覧操作を奪わず、「視差効果を減らす」が有効な場合は縮小表現を省略しても、戻るボタンと下方向ドラッグの意味を維持する。

## 3.1 YamaLensらしいビジュアル方針

YamaLensは「山の名前を当てる道具」だけではなく、登山前の判断材料と自分の記録を持ち歩くアプリである。カメラ画面も、機械的なAR表示ではなく、落ち着いた**登山ノート／フィールドガイド**の印象を目指す。

- 基調色は深いフォレストグリーン、岩肌を思わせるチャコール、紙のようなオフホワイト。警告だけに黄・橙を使う。
- 山のラベルは斜めの大きな札ではなく、丸みを抑えた小さな情報タグにする。
- タグは「山名」「標高」「距離」の3要素を短く整理し、視線を遮らない下寄りの配置を基本とする。
- 山頂へは細いガイド線ではなく、先端に小さな山型マーカーを置いた控えめなリーダー線で結ぶ。
- 選択中の山だけをアクセント色で強調し、他の候補はグレー寄りの控えめな表示にする。
- 下部には候補リストではなく、選択中の山の「ミニ情報カード」を表示する。タップすると天気・小屋・メモのある山詳細へ展開する。
- コンパスは装飾的な大型アイコンにせず、方位と精度を小さく表示するステータス部品にする。

この方針により、既存アプリの構図や部品を模倣せず、YamaLens固有の「情報を確認して次の行動へ進む」体験を作る。

## 3.2 Liquid Glass方針

YamaLensは、iOS 26のLiquid Glassを標準デザイン言語として採用する。ただし、画面全体やすべてのカードを半透明にするのではなく、山の写真・一覧・天気・メモ等の**コンテンツ層**と、その上に浮く**ナビゲーション／操作層**を分ける。

- `TabView`、`NavigationStack`、ツールバー、検索、Menu、sheet、alertなどSwiftUI標準コンポーネントのLiquid Glassを優先する。
- 下部タブ、カメラ上のズーム・手動補正、選択中候補のミニカードなど、コンテンツ上に浮く重要な操作へ使用する。
- 山一覧、天気、施設、メモ、注意カードなどの情報面を一律にガラス化しない。可読性と情報階層を優先する。
- ブランド色のフォレストグリーンは、主要操作または選択状態へ限定して使う。すべてのガラス部品を着色しない。
- 警告色はLiquid Glassの装飾に流用せず、注意理由、アイコン、日時、公式情報への導線と組み合わせる。
- カメラ映像上は背景の明暗が変化するため、文字のコントラストを常に確保する。必要な場合はガラスをより不透明にし、景色を透かすことより読みやすさを優先する。
- 「透明度を下げる」「コントラストを上げる」「視差効果を減らす」の設定に追従し、効果が弱まっても意味と操作を維持する。
- 独自のLiquid Glass部品は標準部品で表現できない重要操作に限定し、過剰な効果による描画負荷と視覚的ノイズを避ける。

具体的なSwiftUI API、独自部品、性能、レビューの規則は [Liquid Glass実装規則](../.agents/skills/develop-yamalens/references/liquid-glass-ui-rules.md) に従う。

## 4. 画面設計

### 4.1 ホーム（山一覧）

**目的**: もっとも確実な入口として、カメラを使わずに山を開けるようにする。

```text
┌──────────────────────────┐
│ YamaLens                    🔍 │
│                              │
│ お気に入り                    │
│ ┌ 丹沢山       1,567m      ★ ┐ │
│ └ 蛭ヶ岳       1,673m      ★ ┘ │
│                              │
│ 最近見た山                    │
│ ┌ 大山         1,252m        ┐ │
│ └ 塔ノ岳       1,491m        ┘ │
│                              │
│ 丹沢の山                すべて > │
│ [大山] [塔ノ岳] [丹沢山] [蛭ヶ岳] │
└──────────────────────────┘
  ホーム          カメラ          マイ
```

- 右上の検索ボタンから専用の検索画面を開く。検索画面では入力欄を最初から操作可能にする。検索と設定のアイコンは視覚上コンパクトにしつつ、44pt以上のタップ領域を維持する。
- 「今の時期の山」は固定された季節メタデータによる紹介とし、登山の安全性や実行を推奨する表現を使わない。
- 「この近くの山」は利用者が位置情報の利用を選んだ場合だけ表示し、初回起動で権限を要求しない。未許可時は用途を示す任意の導線を置く。
- 取得中は進行状態を示し、取得後は150km以内の山を距離順で最大10件表示する。水平精度が25mを超え100m以内の場合は距離と順序が「目安」であることを文字でも示し、100mを超える場合は再取得を案内する。
- 位置情報が拒否・制限・取得失敗の場合も山一覧と検索を残し、設定を開く、検索する、再試行する、のうち状態に合う回復操作を表示する。現在地と位置履歴は保存しない。
- 「設定を開く」から位置情報を許可してアプリへ戻った場合は、権限を再確認して現在地を自動取得し、追加のタップなしで近い山を更新する。
- お気に入りが空の場合は「よく行く山を保存するとここに表示されます」と案内する。
- 山行中で位置情報が使える場合のみ、任意で「現在地から近い山」を追加表示する。
- 各行をタップすると山詳細を開く。カード内に情報を詰め込み過ぎない。

### 4.2 検索・絞り込み

**目的**: 名称が曖昧でも、山域や標高から目的の山を見つける。

- 検索対象: 山名、別名、山域、都道府県。
- 絞り込み: 山域、標高帯、お気に入り、オフライン保存済み。
- 結果行: 山名、標高、山域。位置情報許可時のみ距離・方角を補助表示する。
- 0件の場合は、検索語を変える案内と「丹沢の山を一覧で見る」導線を表示する。

### 4.3 カメラ（山候補）

**目的**: 目の前の山の候補を知り、詳細情報へ移動する。

```text
┌──────────────────────────┐
│ 丹沢パック使用中        北西  ● 精度 良好 │
│                              │
│                              │
│         カメラ映像             │
│                              │
│             ◇ 蛭ヶ岳           │
│                1,673m / 12.4km  │
│                              │
│                  [ 1× | 2× | 3× ] │
│                              │
│ ┌────────────────────────┐ │
│ │ 蛭ヶ岳  1,673m  北西 12.4km      │ │
│ │ 風 8m/s  日没 17:42       詳細 > │ │
│ └────────────────────────┘ │
│ [検索から選ぶ]                    │
└──────────────────────────┘
  ホーム          カメラ          マイ
```

#### 表現方針

- 山頂マーカーと控えめなリーダー線で、カメラ映像上の山と情報タグを結ぶパノラマ型のAR表示とする。
- タグは山の輪郭を隠さないよう、山頂の上または横へ逃がす。近接する候補は高さをずらし、重なりを避ける。
- タグは「山名」「標高」「距離」を2行以内でまとめる。角丸を強くしすぎず、YamaLensのフィールドガイド調の見た目にする。
- 上位の有力候補だけを常時表示する。ほかの候補は下部シートから選べるようにし、ラベル過多を避ける。
- 候補は山頂方向をARKitのカメラ姿勢、内部行列、表示変換で画面座標へ投影し、現在の画角内にある場合だけ表示する。端末を山とは逆方向、上方向、下方向へ向けた場合は、画角外の候補をラベルと下部シートへ残さない。
- カメラ映像上のラベルは最大5件、下部の「この画角の候補」は最大10件とする。画角境界では3度の保持余白を既存候補だけに適用し、候補の頻繁な出入りを抑える。
- 補助表示として、導入済みDEMから計算した山稜線の予測線を表示・非表示できる。実景とのずれを視覚的に確認できるようにし、実景や確定境界ではないことが分かる破線で表示する。詳細パック未導入・高度不明・DEM欠損等で生成できない場合は、推測線を表示せず理由を示す。

#### 手動補正

コンパス・GPSにはずれが生じるため、センサーだけに依存しない。

- 初期位置は端末センサーで自動的に合わせる。
- 下部候補トレイの「方位を調整」から補正モードへ入り、補正モード中だけ画面の横ドラッグを有効にする。
- ユーザーは画面を横方向へドラッグして、山稜線・ラベルを実景に重ねるように微調整できる。
- 補正中は「手動調整中」と表示し、補正量を「東へ4°」「西へ3°」のように示す。
- ドラッグの代替として、44pt以上の「西へ1°」「東へ1°」ボタンを下部に置く。タップでは1°、長押し中は1°刻みで連続補正し、指を離した時点で停止する。
- 「自動に戻す」ボタンでセンサー基準の位置へ戻せる。
- 補正値はカメラセッション中だけ有効とする。カメラ候補から山詳細を直接開いて戻る場合は保持し、ホームまたはマイへ離れた場合は破棄する。別地点や次回の利用へ恒久保存しない。

- 画面上部にオフラインパック名と精度状態を常時表示する。
- 山名ラベルは画面端に重ならない位置へ配置し、最大表示数を制限する。
- ラベルをタップすると山詳細へ遷移する。
- カメラ候補から開いた山詳細を直接閉じた場合は、停止していたカメラセッションを再開して同じカメラ画面へ戻す。ホームまたはマイへ移動した後は自動再開せず、利用者の明示操作で開始する。
- 下部ミニ情報カードには選択中の候補の基本情報、風、日没を表示する。横スワイプまたはタップで別候補を選べる。
- 「検索から選ぶ」は常に表示する。
- 画面下部寄りに `1×`、`2×`、`3×` のズーム切替を置く。選択中倍率を明確に表示し、倍率変更中もラベルを一瞬隠さず再配置する。
- カメラや位置情報が未許可の場合は、プレビューの代わりに権限の用途と許可ボタン、検索導線を表示する。
- 方位または姿勢が利用困難な場合は古い候補を消し、「方位を再確認しています」と状態を示したうえで、「金属や磁石を端末から離し、端末をゆっくり上下左右に動かしてください」と復旧操作を案内する。センサーが有効値を再取得したら、ユーザー操作なしで候補表示へ復帰する。
- 現在地が60秒を超えて古くなった場合は古い位置で候補を表示せず、画面を開いたまま現在地を自動再取得し、取得後に候補表示へ復帰する。
- 手動補正を行う場合は「稜線とラベルを重ねるように左右へ動かしてください」と案内する。
- 映像・位置情報は端末内で処理される旨を、初回説明と設定画面で示す。

### 4.4 山詳細ダッシュボード

**目的**: 登山前・山行中に必要な情報を、鮮度と重要度順で確認する。

```text
┌──────────────────────────┐
│ ‹ 戻る       丹沢山             ☆ │
│ 1,567m   南西 4.2km              │
│                              │
│ ┌ 登山前チェック ────────────┐ │
│ │ 風: 北西 12m/s     注意         │ │
│ │ 日没: 17:42  （あと 2時間）      │ │
│ │ 天気取得: 10分前          詳細 > │ │
│ └────────────────────────┘ │
│                              │
│ ┌ 山頂付近の天気 ────── 詳しく見る > │
│ │ ☁ 8℃   北西 9m/s   降水 20%    │ │
│ │ 12時 8℃ / 15時 6℃ / 18時 5℃   │ │
│ │ 強い風の予報・取得 10分前        │ │
│ └──────────────────────┘ │
│                              │
│ 日の出 5:07        日の入り 18:20   │
│                              │
│ 山小屋                            │
│ ┌ 尊仏山荘 ───────── 公式 ↗ ┐ │
│ │ 提供元・確認日・短い補足          │ │
│ └──────────────────────┘ │
│ 登山口・交通                       │
│ [大倉登山口] [大倉バス停] [駐車場]   │
│                              │
│ 自分のメモ                     編集 > │
│ [登山口までの経路を開く]              │
│ 公式情報・データ出典              > │
└──────────────────────────┘
```

#### 表示順

1. 山名、標高、距離・方角、お気に入り。
2. 登山前チェックカード: 強風、雷・警報、日没までの時間、情報鮮度。
3. 現在の天気と直近予報の概要カード。押下すると時間別予報、注意情報、前日の気象サマリー、日照、提供元をまとめた天気詳細を開く。
4. 山頂座標における当日の日の出・日の入り。
5. 山小屋。
6. 登山口・アクセス、駐車場、交通、温泉。
7. 自分のメモ・確認リスト。
8. 地図アプリでのアクセス検索と公式情報への導線。

- 日の出・日の入りは端末内で計算し、「山頂座標・今日」を明示する。周辺地形による遮りや現地の明るさを反映した時刻とは表現しない。
- 山小屋、登山口・交通、立ち寄り情報を別々のセクションとして表示する。施設カードには種別、名称、短い説明、提供元、最終確認日、外部遷移を表示し、カード全体からHTTPSの公式ページを開く。
- 営業時間、料金、運行状況等の変動値は、確認済みの固定データがない限りカードへ転記せず公式ページへ誘導する。施設未整備の山では架空のカードを表示せず、理由が分かる空状態を表示する。

#### 天気概要と詳細

- 山詳細には、現在の天気、気温、風、取得可能な直近の降水確率、直近3時間、最も重要な注意理由、取得日時を一つの概要カードとして表示する。すべての時間別値や前日サマリーを山詳細へ展開しない。
- 概要カード全体を44pt以上のタップ領域とし、「詳しく見る」とシェブロンを併記する。VoiceOverでは時間別予報と前日サマリーを開く操作であることを読み上げる。
- 概要カードを押すと大きなsheetで天気詳細を開く。sheetは下方向のスワイプと「閉じる」の両方で戻れ、山詳細の閲覧位置を保持する。
- 天気詳細には、対象の山名・標高・山頂付近であること、手動更新、現在値、時間別予報、注意情報、前日の気象サマリー、鮮度、取得日時、提供元・法的情報を表示する。
- 将来の日別予報は、取得済みの実データがある場合だけ天気詳細へ追加する。未実装・未取得の値を固定値や推測値で補わない。日の出・日の入りは気象データと分離し、山詳細で端末計算値を表示する。

#### 注意カード

- 通常: 落ち着いた背景で「情報は◯分前に更新」と表示。
- 注意: 風、雷、警報、日没が近い等で強調色とアイコンを使用する。
- 気象は取得後1時間以内を「最新」、1時間超3時間以内を「更新を推奨」、3時間超を「古い情報」と表示する。
- WeatherKitの現在から12時間以内の予報風速10m/s以上は「風が強い予報」、15m/s以上は一段強い注意として、値と対象時間を併記する。これらを登山可否の文言へ変換しない。
- 現在から12時間以内の雷、雪・みぞれ・着氷性降水、任意の3時間区間で5℃以上の気温低下は、取得できた場合だけ事実と対象時間を表示する。未取得を「なし」と表示しない。
- 公式警報は発表機関名と詳細リンクを表示し、WeatherKitから提供された意味を変更しない。
- 緊急性を示す色だけに依存せず、短いテキストで理由を必ず併記する。
- 「登山可／不可」は表示しない。代わりに公式情報への導線を置く。

#### 前日の気象サマリー

- 現在・これからの予報の直後に「前日の気象サマリー（山頂付近）」を置く。現在予報より強く見せないが、降水量は折りたたまず最初の行で確認できるようにする。
- 最初の行には対象日、降水量、取得できる場合は最高／最低気温を表示し、詳細で降雪量、対象地点、提供元、取得日時を確認できるようにする。
- 「前日は雨」「前日の降水量 12mm」のように取得値を事実として示し、「登山道がぬかるんでいます」「登山に適しません」等へ変換しない。
- 値が欠ける場合は項目ごとに「未取得」、全体を取得できない場合は「前日の情報を取得できません」と表示する。0mm・0cmはWeatherKitが0として返した場合だけ表示する。
- 前日サマリーだけ更新に失敗した場合、現在・予報カードをエラー表示へ変えない。前日部分に再試行と取得日時を表示する。

#### 登山前チェック（将来拡張）

山詳細の最上部に、展開可能な確認カードとして表示する。

```text
登山前チェック                         4 / 6
✓ 丹沢オフラインパック       保存済み
✓ 天気                         20分前に更新
! 風                           山頂付近 12m/s
✓ 日没                         17:42
○ 山小屋                       公式情報を確認する
○ 登山口へのアクセス           地図アプリで確認する
```

- `✓` は確認済み、`!` は注意、`○` は未確認を表す。情報がない項目は「未確認」と明示する。
- 地図アプリ・公式サイトを開く操作から戻った後、ユーザーが確認済みにできる。
- 色だけで状態を示さず、アイコンとテキストを併用する。
- 登山可否を示すスコアや判定は表示しない。

#### アクセスカード

- 「登山口・アクセス」には、主な登山口、駐車場、最寄り駅・バス停を短く表示する。
- 各目的地の「ここへ行く」をタップすると、標準sheetで目的地、出発地、移動手段、地図アプリを確認する。
- 出発地は「現在地」「よく使う出発駅」の選択行とする。駅名が長くDynamic Typeが大きい場合にも対応するため、狭いSegmented Controlへ詰め込まない。
- 「現在地」はYamaLensの位置情報権限に依存せず、地図アプリ側の現在地を使用する。「よく使う出発駅」が未登録の場合は、選択行の代わりに「出発駅を登録」を表示する。
- 標準はAppleマップとし、Google Mapsがインストールされている場合だけ選べる。
- YamaLens内では道順を表示しない。地図・ナビゲーションは選択した地図アプリへ委ねる。
- 圏外時は「地図アプリで経路を取得できない場合があります」と表示し、目的地・登録駅の名称と公式アクセス情報は閲覧可能にする。

```text
┌──────────────────────────┐
│ ここへ行く                    完了 │
│                              │
│ 目的地                           │
│ 大倉登山口                        │
│                              │
│ 出発地                           │
│ ✓ 現在地                         │
│   よく使う出発駅  秦野駅           │
│                              │
│ 移動手段                 公共交通 > │
│ 地図アプリ              Apple Maps > │
│                              │
│ [経路を開く]                     │
└──────────────────────────┘
```

- sheetは標準の選択部品とButtonを使い、各選択行と実行ボタンを44pt以上にする。
- VoiceOverでは、目的地、選択中の出発地、移動手段、地図アプリ、外部アプリを開くことを読み上げる。

### 4.5 山小屋・アクセスなどの詳細リスト

**目的**: ダッシュボードでは収まらない情報を、種別ごとに確認する。

- リストの1行には名称、短い補足、最終確認日を表示する。
- 営業情報や運行情報など変動する内容には「公式情報を確認」リンクを優先して置く。
- 外部サイトを開く直前に、対象となる運営者名と「Safariで開く」ことを分かるようにする。

### 4.6 メモ編集

- 「行く前」「山行中」「行ったあと」に分けた自由記述メモ、行きたい時期、確認リスト、お気に入り、手動の登頂済み状態を編集する。
- 登頂済みは利用者が明示的に切り替える記録であり、GPS活動記録や登頂の自動判定を行わない。
- 保存は明示ボタンとし、未保存変更がある状態で戻る場合は確認する。
- メモは端末内保存であることを画面下部に表示する。

### 4.7 マイ／オフラインパック管理

```text
┌──────────────────────────┐
│ オフラインパック             管理 │
│                              │
│ オフラインパック                │
│ ┌────────────────────────┐ │
│ │ 丹沢山地                     保存済み │ │
│ │ 218 MB / 更新: 2026-08-17       > │ │
│ └────────────────────────┘ │
│ お気に入り                    4件 > │
│ 最近見た山                    6件 > │
│                              │
│ [パックの更新を確認]              │
└──────────────────────────┘
```

- オフラインで使える山域、容量、最終更新日を一目で示す。
- 詳細パックの配信開始前は、アプリ内蔵の基本データを「利用可能」、詳細地形・施設データを「未導入／提供前」と分けて表示する。動作しない仮のダウンロードボタンは表示しない。
- 内蔵基本データは「丹沢の山」と「周辺候補」の件数を分けて示す。周辺候補は富士山等をARで見分けるための補助データであり、丹沢以外のパックを保存済みとは表現しない。
- MVPでは丹沢パックだけを表示する。奥多摩、富士山、八ヶ岳などMVP後の山域を保存候補として表示しない。
- 自動保存は初期状態ではオフとする。有効にした場合は「Wi-Fi時のみ」を初期値とし、設定画面からモバイル通信利用を変更できる。
- 更新中は進捗・残り容量を表示し、完了前の旧パックを保持する。
- 削除操作は確認ダイアログを出し、個人メモは削除しないことを明示する。

### 4.8 初回説明・権限

初回起動は、説明を3画面以内に収める。

1. 「山を調べる。見えている山を知る。」
2. 「丹沢パックを保存すれば、圏外でも山候補を表示できます。」
3. 「カメラ・位置情報は山候補表示にのみ使います。映像と位置情報は端末外へ送信しません。」

権限は機能を使う直前に要求し、拒否時は検索・一覧の代替導線を提示する。

### 4.9 設定

**目的**: 通信量、端末容量、権限、データの鮮度をユーザーが自分で管理できるようにする。設定項目を増やし過ぎず、通常の利用で変更するものに限定する。

```text
┌──────────────────────────┐
│                    設定     │
│                              │
│ オフラインパック                │
│ 自動ダウンロード          オフ  > │
│ 保存容量の上限              1 GB > │
│ 保存済みパックを管理              > │
│                              │
│ カメラ・位置情報                  │
│ カメラ                    許可済み > │
│ 位置情報                  使用中のみ > │
│                              │
│ アクセス                          │
│ よく使う出発駅               秦野駅 > │
│                              │
│ データ・プライバシー                │
│ 気象とデータの出典                > │
│ プライバシー                       > │
│ 診断ログ（開発モード時のみ）        > │
│                              │
│ アプリ情報                         │
│ YamaLensについて                  > │
│ バージョン 0.1.0                   │
└──────────────────────────┘
```

#### オフラインパック設定

- **自動ダウンロード**: 初期値はオフ。有効にすると「Wi-Fi接続時のみ」「モバイル通信も使用」の選択肢を表示する。
- **保存容量の上限**: 初期値は1GB。上限到達前に、追加予定パックの容量と削除候補を表示する。
- **保存済みパックを管理**: 各パックの追加、更新、削除、容量、最終更新日を確認できる。削除してもメモ・お気に入りは残ることを明示する。

#### カメラ・位置情報設定

- 権限の現在状態を表示し、変更が必要な場合はiOSの設定画面へ遷移する。
- AR表示の手動補正はカメラ画面のセッション内操作で完結し、設定画面には置かない。
- ラベルの表示数やズーム倍率など、検証段階で必要な詳細設定は開発者用画面に限定し、通常の設定画面には出さない。

#### アクセス設定

- SwiftUI標準の `Form` と検索UIを使い、「よく使う出発駅」を1件だけ検索・登録・変更・削除できるようにする。
- 検索結果には駅名と所在地を表示し、同名駅を区別できるようにする。結果選択前に登録内容を確認する。
- 駅検索には通信が必要であることを明示する。検索失敗・0件の場合も入力文字列を保持し、再試行またはキャンセルできるようにする。
- 登録駅の利用にYamaLensの位置情報権限は不要であり、検索語は保存しないことをプライバシー説明へ記載する。

#### データ・プライバシー

- 気象、地形、施設などの出典・利用条件を確認できる。
- WeatherKitの帰属表示と法的リンク、国土地理院データの出典と加工表示を確認できる。
- カメラ映像、位置情報、個人メモ、よく使う出発駅の端末内処理方針を簡潔に表示する。駅の検索語と検索履歴を保存しないことも明示する。
- 開発モード時だけ表示する診断ログ画面では、保存件数、各ログの保存日・削除予定日・保持指定を確認し、個別削除と全削除を行える。通常利用では記録を開始しない。
- Debugビルドのカメラ画面には小さな「診断記録」操作を表示する。開始後は赤い記録状態、サンプル数、問題マーカー、目視で確認した山、保存、破棄を表示し、カメラ映像を保存しないことを診断ログ画面で明示する。保存と破棄は片手で届く操作面に置き、破棄は確認を挟む。
- 診断ログ詳細では、記録時のラベルを橙、現在の候補計算を緑として同じ疑似画角へ重ね、スライダー、前後ボタン、自動再生でサンプルを移動できるようにする。現在の計算は保存済み5Hzサンプルを先頭から処理し、安定化状態を含めて再計算する。両方に存在する候補は平均・最大の画面位置差を表示し、問題マーカーから該当時刻へ移動できるようにする。正確な座標は開発画面内だけに表示する。
- 診断ログの共有は「匿名化サマリー」を既定とする。正確な座標を含むリプレイ用を選んだ場合は、含まれる項目をプレビューし、「正確な位置を含めて共有」の追加確認を行う。
- AI機能を将来有効化した場合のみ、AIへの送信内容・利用上限・オン／オフをこの画面に追加する。

#### 危険な操作

- パック削除、全キャッシュ削除、メモの全削除は確認ダイアログを必須とする。
- メモ全削除はオフラインパック削除とは別の操作にし、初期画面には置かない。

### 4.10 将来拡張: 登山予定日の前日通知

- 登山予定日を登録した画面に「前日に通知」Toggleを置き、既定はOFFとする。通常の初回説明やアプリ初回起動では通知権限を求めない。
- 最初にToggleをONにした直後、前日確認を促す用途と、通知が最新気象や安全を保証しないことを説明してからシステム権限を要求する。
- 初期通知時刻は前日18時とし、予定ごとに変更できる。権限拒否時はToggleを有効に見せず、「iOSの設定を開く」と通知なしで前日確認を使えることを示す。
- 通知をタップすると対象の山詳細へ移動し、通信可能なら気象更新を試す。本文は既定で山名や気象値をロック画面へ露出させず、「予定している山の情報を確認してください」とする。
- 通知は配信保証、緊急警報、気象警報の代替として表現しない。

## 5. 共通コンポーネント

| コンポーネント | 用途・ルール |
| --- | --- |
| 山カード | 山名、標高、山域、必要に応じて距離・方角。タップ領域は十分に大きくする。 |
| 情報鮮度ラベル | 「更新: 10分前」「保存済み: 昨日」など、すべての変動データに付与。 |
| 公式リンク行 | 外部遷移アイコン、提供元名、最終確認日を表示。 |
| 注意カード | 理由、取得時刻、公式情報への導線を含める。 |
| オフライン状態 | 「丹沢パック使用中」「通信なし。保存済み情報を表示中」など短く示す。 |
| 空状態 | 何もない理由、次にできる操作を1つだけ案内する。 |
| Liquid Glass操作面 | ナビゲーション、カメラ上の主要操作、選択中候補に限定する。情報カードへ一律適用しない。 |

## 6. 色・文字・アクセシビリティ

- ベースは白または濃色のどちらでも視認性を確保し、屋外での高コントラストを優先する。
- 標準状態は自然を想起する深い緑または青緑をアクセントに使う。警告は黄・橙・赤を意味づけとテキストで併用する。
- 本文はDynamic Type対応。重要な数値（風速、日没までの時間など）は本文より大きく表示する。
- タップ領域は原則44pt以上とする。
- アイコンだけで状態を伝えず、VoiceOver用のラベルを付与する。
- カメラ画面ではラベルに背景・影を付け、明暗のある山景色でも読めるようにする。
- Liquid Glassは「透明度を下げる」「コントラストを上げる」「視差効果を減らす」で意味と操作を失わないようにする。

## 7. 主な状態別の表示

| 状態 | UIの扱い |
| --- | --- |
| 圏外 | 上部に「通信なし」。気象等は最終取得時刻付きで表示し、更新ボタンは無効化する。 |
| 丹沢パック未保存 | カメラ画面に「オフライン用の丹沢パックを保存してください」と表示。通信可能なら保存画面へ誘導する。 |
| 位置・カメラ未許可 | 機能を使う目的と許可ボタン、検索へ戻るボタンを提示する。 |
| 方位精度が低い | 古い候補を消し、「方位を確認中」と磁石・金属から離れる案内を明示する。有効値の再取得後は自動復帰する。 |
| データが古い | 数値の近くに最終取得時刻を置き、公式サイトへの導線を強調する。 |
| 情報なし | 「未確認」と表示し、推測値・空のカードで埋めない。 |
| 前日気象だけ取得失敗 | 現在・予報は通常表示し、前日の領域だけ「取得できません」と再試行を表示する。 |
| 出発駅未登録 | 「ここへ行く」で現在地は選択でき、登録駅の位置には「出発駅を登録」を表示する。 |
| 駅検索が通信不可・0件 | 入力を保持し、理由、再試行、キャンセルを駅検索画面内に表示する。 |

## 8. UI受け入れ条件

1. 初めて使うユーザーが、ホームから検索して任意の山の詳細を開ける。
2. 位置情報やカメラを許可しなくても、一覧、検索、山詳細、メモを利用できる。
3. カメラ画面で、オフライン中であること・使用中の山域パック・候補精度を確認できる。
4. 山詳細の最初の画面内で、風、日没、天気取得時刻、公式情報への導線を確認できる。
5. 変動する情報には、少なくとも取得時刻または最終確認日が表示される。
6. 未許可・圏外・パック未保存・精度低下の各状態で、ユーザーが次に取るべき操作を一つ理解できる。
7. 主要な操作は片手で届く下部領域または下部タブから行える。
8. Liquid Glassがナビゲーションと重要な操作に限定され、情報コンテンツの可読性を妨げない。
9. Light／Dark、透明度を下げる、コントラストを上げる、視差効果を減らす、Dynamic Type拡大でも主要情報と操作を認識できる。
10. 開発モードの診断ログは記録開始前に保存されず、保存日・削除予定・保持指定を確認して個別または全件削除できる。
11. 正確な位置を含む診断ログを共有する場合、共有内容のプレビューと追加確認が表示される。
