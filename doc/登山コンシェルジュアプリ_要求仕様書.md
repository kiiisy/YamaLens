# YamaLens 要求仕様書

- 文書バージョン: 0.4
- 作成日: 2026-08-17
- 更新日: 2026-08-25
- 対象: iPhone 15 Pro 以降向け自作 iOS 26 アプリ

## 1. 目的

登山前・登山中に必要な周辺情報を素早く確認できる、独立した情報確認アプリを作る。

ユーザーがカメラを山へ向けて候補の山を特定し、山名・標高・距離・方角に加え、山小屋、登山口へのアクセス、駐車場、公共交通、温泉、山頂付近の気象、日の出・日の入り、公式情報、自分用メモを、一つのダッシュボードで確認できることを目指す。

ルートの詳細確認、登山地図、GPS 軌跡、活動記録は本アプリでは扱わない。

## 2. プロダクトの位置づけ

| 領域 | 本アプリでの扱い |
| --- | --- |
| 山の特定 | カメラと位置情報から候補を表示 |
| 登山前の確認 | 天気・小屋・交通・注意点を集約 |
| ルート・地図 | 原則扱わない |
| 活動記録・GPS軌跡 | 原則扱わない |
| 個人メモ | 山ごとに保存・表示 |

## 3. 想定ユーザー

- 日本国内で日帰り登山または山小屋泊登山をする、iPhone 15 Pro 以降の利用者。
- ルート・地図アプリとは別に、出発前に散在する情報を短時間で整理したい人。
- 行きたい山、よく登る山、山小屋や交通手段の情報を自分用に蓄積したい人。

## 4. スコープ

### 4.1 対象（In scope）

- 現在地・カメラの向き・端末姿勢を用いた、見えている山の候補表示。
- 山の基本情報と登山周辺情報の集約表示。
- 山頂付近を基準とした気象・日照情報の表示。
- 山小屋、複数登山口、登山口ごとの駐車場・バス／ロープウェイ・代表的な温泉、公式リンクの表示。登山口・最寄り駅周辺のコンビニ、食事、追加の温泉候補を外部地図で検索する導線。
- よく使う出発駅を1件登録し、現在地または登録駅から選択した目的地までの経路検索を外部地図アプリで開く。
- 個人メモ、お気に入り、確認済み項目、「気になった山」の現地記録の保存。
- 取得済みデータを使った AI による「登る前の確認事項」の要約（将来拡張）。
- オフライン時の基本情報・個人データの参照、およびカメラからの山候補特定。

### 4.2 対象外（Out of scope）

- ルート作成、登山地図の提供、ナビゲーション、現在地追跡。
- 活動記録、SNS 投稿、他ユーザーとの共有。
- 遭難救助の判断、危険判定、登山可否の保証。
- 山小屋・交通機関の予約、決済。
- 気象・交通・営業情報の正確性を保証すること。

## 5. 主なユースケース

1. 登山者が展望地点でカメラを山に向け、候補から「槍ヶ岳」を選ぶ。
2. アプリは山名、標高、現在地からの距離・方角を即時に表示する。
3. ユーザーは山詳細ダッシュボードで、山頂予報、山小屋の営業情報、登山口までの交通、駐車場、日の出時刻を確認する。
4. ユーザーは「登る前に確認すべきこと」を実行し、取得済み情報に基づく要約と、公式情報を確認するリンクを得る。
5. ユーザーは「9月下旬に行きたい」「小屋は要予約」などのメモを保存する。
6. ユーザーは前日の山頂付近の降水量等を確認し、現在・予報・公式情報と合わせて判断材料にする。
7. 電波圏外では、事前に保存・同期済みの山基本情報、メモ、お気に入り、「気になった山」の記録と写真、直近の取得情報（取得時刻付き）を閲覧する。

## 6. 機能要件

### 6.1 山の特定

- 山の特定は、画像を外部サービスへ送って認識する方式ではなく、現在地・端末方位・端末姿勢と、端末内の山頂データを照合して行う。通信は必須としない。
- カメラプレビュー上に、現在地、方位、端末の傾き、登録済み山データから算出した山候補を重ねて表示する。
- カメラ画面ではズームを利用できる。ズーム倍率・使用中レンズの画角に応じて、山候補ラベルの位置を再計算する。
- 候補ごとに山名、標高、距離、方角、推定一致度を表示する。
- 候補はタップして確定でき、検索から手動選択もできる。
- 位置情報または方位の精度が低い場合は、その旨と手動検索導線を表示する。
- 山の誤同定を防ぐため、特定結果は「候補」として扱い、確定の自動保存はしない。
- オフライン用に保存した山域では、通信がない状態でも山候補、山名、標高、距離、方角を表示できる。
- 候補の算出には、現在地から見た方位・仰角・距離を用いる。地形データを保存している場合は、稜線等による見通し判定にも利用する。
- 方位精度、位置精度、端末の傾き、視界不良などにより信頼できない場合は、候補数を絞り過ぎず、精度低下の表示と手動選択を提供する。

### 6.1.1 一覧・検索による山の選択

- カメラや位置情報を利用しなくても、山一覧および検索から山詳細を開ける。
- 山名、別名、山域、都道府県、標高帯を対象に検索・絞り込みできる。
- 気になった山、お気に入り、最近見た山、オフライン保存済みの山を一覧で確認できる。
- 一覧の各項目には、少なくとも山名、標高、山域、お気に入り状態を表示する。
- 位置情報を許可している場合は、現在地から近い順での並べ替えを提供する。位置情報を許可しない場合でも全機能の閲覧・検索を利用できる。
- ホームには、同梱の軽量丹沢データにある固定の季節メタデータから「今の時期の丹沢」を表示する。詳細オフラインパック、通信、位置情報、天気の有無に依存させず、登山可否や安全性の推薦として扱わない。
- 「この近くの山」は、利用者が位置情報を許可し、対応済みデータ内で150km以内の候補を取得できた場合だけ表示する。対応地域外などで候補がない場合、遠い丹沢の山を近い山として代替せず、理由と山名検索の導線を表示する。

### 6.2 山情報ダッシュボード

選択した山について、以下を一画面（縦スクロール可）で確認できること。

- 基本情報: 山名、別名、標高、現在地からの距離・方角、位置、最終更新日。
- 気象: 現在・時間帯別・日別の気温、体感温度、風速、風向、降水確率／降水量、雲量、降雪の有無・予測、雷リスクまたは雷情報、気象警報・注意報、および前日の降水量・降雪量・最高／最低気温（取得可能な場合）。
- 日照: 日の出、日の入り、薄明の時刻（データ取得可能な場合）。
- 山小屋: 名称、位置、営業期間、予約要否、連絡先、公式サイト、最終確認日。営業期間、予約要否、収容人数、料金等は、確認済みの値がある項目だけを詳細内で構造化して表示し、未確認値を推測で補わない。
- 登山口アクセス: 登山口候補、所在地、アクセス手段、参照元リンク。
- 外部地図でのアクセス: 登山口、駐車場、最寄り駅・バス停等の目的地を選び、「現在地」または端末内に登録した「よく使う出発駅」を出発地として経路検索を地図アプリで開ける。車・徒歩・公共交通の選択肢を提示する。地図アプリは設定でApple Maps（既定）、Google Maps（インストール済みの場合のみ）、毎回選択から選べる。
- 公式サイト: アプリ内WebViewを使わず、既定のブラウザ、Chrome（インストール済みの場合のみ）、毎回選択から設定した外部ブラウザで開ける。Safariは既定ブラウザとして扱う。
- 外部登山サービス: 検証済みYAMAP山ページが登録された山では「YAMAPで見る」を表示する。インストール済みならUniversal Linkでアプリ、未導入ならWebを開き、対象の山ページからYAMAP側の登山計画作成へ進める。YamaLensはYAMAPのアカウント、ルート、計画、活動記録を取得・保存しない。ヤマレコはMVP対象外とする。
- 立ち寄り検索: 登山口または最寄り駅の周辺を指定し、コンビニ、食事、追加の温泉候補を外部地図アプリで検索できる。カテゴリと地図の中心地点を分けて渡す。YamaLens内では登録済みの代表的な温泉だけを表示し、周辺店舗を網羅した一覧や営業中かどうかを表示しない。
- 駐車場: 名称、位置、収容台数、料金、季節運用、混雑・予約情報へのリンク（取得可能な範囲）。
- 公共交通: バス、ロープウェイ、鉄道等の利用候補、公式時刻表・運行情報リンク。
- 温泉: 下山後に利用しやすい候補、位置、営業時間・休業情報への公式リンク。
- 公式情報: 行政、山域管理者、山小屋、交通事業者などの一次情報リンク。
- ユーザーデータ: メモ、お気に入り、行きたい時期、確認チェックリスト、最終閲覧日、「気になった山」の現地記録。
- 山詳細の写真: 既定のイラストを表示し、ユーザーは端末内の写真を山ごとに設定・変更できる。選択写真はホーム等の山カードと山詳細への遷移にも共通して表示する。写真をクラウドへ送信・共有しない。
- 山ノート: 「行く前」「山行中」「行ったあと」を直接選んで各メモを入力でき、長押しで保存済みメモのプレビューを確認できる。

### 6.3 気象表示と注意表示

- 気象データには対象地点（原則: 山頂座標または選択した代表地点）、予報発表時刻、取得時刻、データ提供元を表示する。
- 気象が古い、未取得、圏外である場合は、最終取得時刻と「最新情報は公式情報で確認」の表示を行う。
- 取得後1時間以内を「最新」、1時間超3時間以内を「更新を推奨」、3時間超を「古い情報」とする。通信可能で前回取得から30分を超えている場合は、山詳細表示時に更新を試す。
- 強風、雷、警報・注意報、急な気温低下など、定義した閾値または提供元の警戒情報に該当する場合は目立つ注意カードを表示する。
- WeatherKitの現在から12時間以内の予報風速10m/s以上、15m/s以上を段階の異なる注意表示とする。気象庁の平均風速区分は初期値の参考とし、安全判定には使わない。同じ12時間以内の雷、雪・みぞれ・着氷性降水、任意の3時間区間で5℃以上の気温低下は、取得できた場合に値と対象時間を表示する。
- 公式警報は発表機関と提供された詳細リンクを表示し、内容を独自の安全判定へ変換しない。
- 注意カードは判断支援であり、登山可否を断定しない文言にする。
- 前の暦日のWeatherKit日別サマリーを「前日の気象サマリー（山頂付近）」として現在・予報より下に表示し、対象日、対象地点、提供元、取得日時を示す。直接観測した実績、登山道の乾燥・ぬかるみ、安全性として表現しない。
- 前日サマリーは同じ対象日の取得から6時間以内をキャッシュとして利用する。取得失敗や一部項目の欠損を、降水なし・降雪なしへ置き換えず、現在・予報の表示は継続する。

### 6.3.1 出発駅と外部経路検索

- 設定で「よく使う出発駅」を1件登録・変更・削除できる。JR・私鉄・地下鉄を含む、地図アプリで検索できる正式名称を利用者が入力し、名称だけをSwiftDataへ端末内保存する。入力した名称は外部地図を開く時にだけ出発地検索語として渡し、検索履歴は保存しない。
- 登山口アクセスで「公共交通」または「車」と対象施設を選んで「地図を開く」と、「ここへ行く」画面に目的地と出発地を表示する。移動手段は登山口アクセスでの選択をそのまま使い、この画面では表示・再選択させない。出発地を「現在地」「よく使う出発駅」から選び、「地図アプリで経路を検索」を押すと設定済み地図アプリを開く。
- 現在地を選んだ場合、現在地の解決は外部地図アプリへ委ねるため、この操作だけを理由にYamaLensの位置情報権限を要求しない。
- 登録駅は設定画面または「ここへ行く」画面の登録導線から任意に登録でき、経路検索の必須条件にしない。位置情報拒否時も登録駅または地図アプリ側の現在地を利用できる。
- YamaLens内では経路、所要時間、地図アプリが算出する料金・運行状況を計算・表示・保証しない。承認済みの公式情報源から取得した施設・交通の案内は、取得日時付きの参考情報として別に表示できるが、リアルタイム状態とは表現しない。Apple Mapsを既定とし、Google Mapsが利用可能な場合だけ選択肢へ追加する。地図アプリの選択は設定に保存でき、必要なら毎回選ぶこともできる。

### 6.4 AI 要約（将来拡張・優先度: 低）

- API 利用料が発生するため、MVP の必須機能には含めない。費用・利用上限・プライバシー方針を確定した後に導入を判断する。
- 導入する場合、ユーザーが明示的に実行したときのみ、取得済みの気象、山小屋、交通、メモ、公式リンクを用いて要約を生成する。
- 出力には、少なくとも「天候」「山小屋」「交通・アクセス」「出発前に確認すること」「参照元」を含める。
- 取得時刻が古い情報、欠損情報、推測を明確に区別する。
- 「登ってよい／危険だから登るな」などの断定や、救助・医療・気象専門家に代わる助言はしない。
- 回答の各重要項目から、元となる公式情報またはデータ提供元へ遷移できるようにする。
- AI 利用時に送信される情報の範囲を示し、ユーザーが実行前に確認できるようにする。

### 6.5 個人メモ・お気に入り・気になった山・登頂済み

- 山ごとに「行く前」「山行中」「行ったあと」の自由記述メモ、行きたい時期、お気に入り、確認項目、手動の登頂済み状態を保存・編集・削除できる。
- 登頂済みはユーザーが明示的に切り替える。GPS活動記録、登頂の自動判定、登山履歴のクラウド共有は行わない。
- 個人メモは原則端末内に保存し、クラウド同期を導入する場合はユーザーの明示的な有効化を必要とする。
- お気に入り一覧から山詳細へ移動できる。
- 「気になった山」は、AR候補を選択した後に利用者が明示的に撮影・保存した現地記録とする。お気に入りの切替だけで撮影・保存しない。
- 記録には、アプリ専用領域へ保存する写真、選択した山、撮影日時、候補として選択した状態、任意のメモを含める。候補を確定した同定結果として表示しない。
- 正確な視点位置は、利用者が記録ごとに「正確な視点位置を端末内に保存」を明示して有効化した場合だけ、座標、水平精度、取得日時を保存する。位置を保存しなくても記録を作成できる。
- 記録の一覧・詳細から、写真、メモ、保存済みの視点位置を削除できる。削除時は写真と視点位置も同時に消えることを確認してから実行する。

### 6.6 オフライン利用

- 通信がない状態でも、事前に保存または閲覧済みの山基本情報、山小屋等のキャッシュ、メモ、お気に入り、「気になった山」の記録と写真を表示できる。
- オフラインパックには、対象山域の山頂データ（名称、座標、標高、別名）、山域境界、候補算出に必要な地形・標高データを含める。これによりカメラからの山候補特定を行う。
- 丹沢パックには、丹沢外から目視され得る富士山等の主要山頂をAR識別用の「周辺候補」として含める。周辺候補の収録は、その山域の施設・地形・詳細情報まで対応済みであることを意味しない。
- オフラインでは更新を必要とする気象・営業・運行情報を更新しようとせず、最終取得時刻を表示する。
- ユーザーはお気に入りの山を「オフライン用に保存」できる。保存対象・容量・更新日時を確認できる。
- 初回利用前に、登る予定の山域をオフライン保存する導線を提供する。未保存の山域では、カメラ候補特定が限定的または利用不可であることを明示する。
- ユーザーはオフラインパックを一覧から追加・更新・削除できる。更新先は署名済み配布一覧で指定する。削除しても個人メモ、お気に入り、「気になった山」の記録と写真は削除しない。
- 個人利用MVPでは丹沢だけを配布対象とし、手動の導入・更新・削除を提供する。近隣山域の提案、自動ダウンロード、モバイル通信の選択はMVP後に追加する。

## 7. 非機能要件

- 開発環境: Xcode 26 を使用する。
- 対応 OS: iOS 26 のみを対象とする。旧OSおよび旧Xcodeとの互換性はMVPでは考慮しない。
- 対応端末: iPhone 15 Pro、iPhone 15 Pro Max、および後継の Pro モデル。iPad は対象外とする。
- 端末前提: カメラ・GPS・コンパス・ジャイロ／加速度センサーを利用する。特定端末に絞ることで、カメラ画角・センサー精度・表示調整の検証対象を限定する。
- 表示性能: キャッシュ済み山詳細は通常操作で 1 秒程度以内に表示することを目標とする。
- 可用性: 外部サービスの障害時も、端末内データと個人メモの閲覧を継続できる。個人ストア破損時も自動初期化せず、山一覧・検索・基本詳細は継続する。
- エラー処理: 一時的な失敗、利用者操作待ち、データ不正、機能制限、内部不具合を区別し、理由、利用可能な代替、再試行または設定導線を示す。データ不正を自動再試行しない。
- プライバシー: 位置情報・カメラ・将来のAI送信情報は目的別に許可を求め、不要な常時位置情報収集は行わない。「気になった山」の写真はアプリ専用領域だけに保存し、記録ごとに明示して有効化しない限り正確な視点位置を保存しない。よく使う出発駅名は端末内へ保存し、登録駅名以外の検索履歴は保存しない。Privacy Manifestを実際のAPI利用と一致させる。
- セキュリティ: APIキーをアプリ内に直接埋め込まない。HTTPSとApp Transport Securityの標準設定を使用し、受信したパック、SQLite、URLを検証してから利用する。個人データと診断ログへ端末のFile Protectionを適用する。
- アクセシビリティ: Dynamic Type、VoiceOver、十分なコントラスト、色だけに依存しない警告表示に対応する。
- 言語: MVP は日本語。データ構造は将来の多言語化を妨げない。
- ログ: 通常ログは匿名・最小限とし、正確な位置履歴を既定で収集しない。開発用診断ログは明示操作で記録開始・保存した場合だけ端末内へ残し、カメラ映像を含めない。30日または20件を初期上限として、同じ入力で候補を再計算でき、共有前に内容を確認できるようにする。

### 8.2 データ品質・更新方針

- 変動の大きい情報（天気、営業、運行、通行情報）は、表示時刻と出典を必須とする。
- 山小屋・交通・駐車場は情報が古くなるため、各レコードに「最終確認日または取得日時」と「公式ページ」を持つ。
- 名称・位置・公式URL等の基本情報は初回登録時に確認し、営業期間、臨時休業、運行案内等の変動情報は、利用条件等を確認した承認済みの公式情報源から低頻度で自動取得できる。
- API、RSS、GTFS等の構造化データを優先し、Webページから取得する場合は情報源ごとの専用抽出規則を使用する。汎用的・無差別なスクレイピングや、アプリからの直接巡回は行わない。
- 自動取得結果には取得日時と出典を持たせる。取得失敗時は未取得値を補完せず、直前の正常な値を古い情報として表示して公式ページへ誘導する。
- 個人利用MVPのWeatherKit応答は端末内で再利用する。複数ユーザー対応時は、全国の登録山を一括定時取得せず、実際に閲覧された山を中心に山ID・山頂座標単位の共有キャッシュを用いる。同一山の同時要求を一つへまとめ、未閲覧・未配布山域の予報を先回りして取得しない。
- 不明な項目は推測で補完せず、「情報未確認」と表示する。
- 収集・利用するデータのライセンス、利用規約、表示義務をデータ提供元ごとに確認する。

## 10. 画面構成

1. **ホーム／山一覧**: 今の時期の丹沢、気になった山、お気に入り、最近見た山、オフライン保存済みの山、検索への導線。
2. **山検索・候補選択**: 山名・別名・山域・都道府県・標高帯から検索・絞り込みし、山を選択。
3. **カメラ／山候補（任意の選択導線）**: カメラプレビュー、山候補、現在地・方位精度、手動検索。
4. **山詳細ダッシュボード**: 基本情報、気象、アクセス、小屋、施設、日照、メモ、公式情報を集約。
5. **AI 登山前チェック（将来拡張）**: 要約、未確認情報、注意事項、参照元リンク。
6. **メモ編集**: 自由メモ、行きたい時期、チェックリスト、お気に入り設定。
7. **気になった山の記録一覧・詳細**: 撮影写真、選択した山、記録日時、任意メモ、明示保存した場合だけの視点位置、削除。
8. **お気に入り／オフライン保存一覧**: 保存済みの山、最終更新日、容量、更新操作。
9. **設定・データ出典**: よく使う出発駅、権限、キャッシュ、データ提供元、プライバシー、免責事項。AI送信設定はAI機能を導入する場合だけ追加する。

## 11. MVP（最初に完成させる範囲）

ここでいうMVPは、開発者本人が継続利用してオフライン候補表示とデータ更新を検証できる最小完成形である。App Store公開、第三者利用、問い合わせ・利用規約等の公開運用は、MVPの完了条件に含めない。

### 初期対応エリア

- MVP の初期正式対応エリアは**丹沢山地（関東）**とする。
- 山頂データ、地形・標高データ、山小屋、登山口、駐車場、交通、温泉、公式リンクは丹沢山地を優先して整備する。
- 山候補特定の開発中の精度検証は丹沢へ限定せず、高尾・陣馬、奥多摩、箱根・富士山周辺、訪問可能なアルプスの一部等から、天候と移動機会に合わせて選んだ複数山域で実施する。
- 丹沢外の検証地域には、山頂・周辺候補・DEM・出典を中心とする開発用ARテストパックを使用できる。テストパックは山詳細、施設、気象、アクセスの網羅性を保証せず、正式対応地域として表示しない。
- 他の関東近郊山域への対応は、丹沢山地での精度・データ更新運用を検証した後に追加する。
- 周辺機能と丹沢データの開発は現地AR検証と並行し、視界不良や訪問延期だけを理由に停止しない。

### Must

- 手動検索で山を選べること。
- 山一覧から、気になった山・お気に入り・最近見た山・オフライン保存済みの山を開けること。
- 詳細オフラインパック未導入、通信なし、位置情報未許可のいずれでも、同梱データから「今の時期の丹沢」を表示できること。
- 山名、別名、山域、都道府県、標高帯による検索・絞り込みができること。
- オフライン保存済みの山域では、通信がない状態でも、位置・方位・端末姿勢と端末内データを使い、カメラ画面に山候補を表示できること。
- 山名、標高、距離、方角を表示できること。
- 気温、風速・風向、降水、雲量、日の出・日の入りを表示できること。
- 前日の山頂付近の日別気象サマリーを、現在・予報と区別して表示できること。
- 山小屋、登山口、駐車場、交通、温泉、公式情報を、少なくともリンクを含めて表示できること。
- 個人メモとお気に入りを端末内へ保存できること。
- AR候補を選択した後、利用者の明示操作で写真を撮影して「気になった山」として端末内へ記録できること。任意メモを残せ、正確な視点位置は記録ごとの明示操作がある場合だけ保存できること。
- よく使う出発駅を端末内へ1件保存し、現在地または登録駅を選んで外部地図の経路検索を開けること。
- オフライン時に保存済みの基本情報・メモを閲覧でき、更新情報には取得時刻を表示すること。
- Cloudflare R2の静的HTTPS配信から、丹沢詳細パックを手動で導入・更新・削除できること。更新先は署名済み配布一覧で指定し、検証失敗時は直前の正常なパックを保持すること。

### Should（MVP 後半または次リリース）

- 地形データを使った見通し判定により、稜線の裏側などの候補を抑制すること。
- 山小屋の営業期間・予約要否を構造化して表示する。
- 自動ダウンロード、Wi-Fi時のみの取得、近隣山域パックの提案。
- 気象警戒情報を注意カードとして表示する。

### Could（後回しにできるもの）

- ライブカメラ上の高精度 AR ラベル表示。
- AI による登山前チェック（利用量・費用の上限、送信データ、出典・免責表示を確定したうえで導入する）。
- 交通のリアルタイム運行情報。
- 写真のフォトライブラリ保存・共有、カレンダー連携、登山予定日前日のローカル通知。

## 12. 将来拡張

- **登山前チェック（非AI）**: オフラインパック、気象更新日時、日没、山小屋公式情報、登山口までのアクセスなどを、確認済み・注意・未確認の状態で一画面に整理する。登山可否は判定しない。
- **AR表示付き写真の保存・共有**: 「気になった山」のアプリ内写真とは別に、カメラ画面の山名・標高・距離等を重ねた写真を、ユーザーの操作と保存先の確認を経てフォトライブラリ保存または共有できるようにする。
- **登山予定日と前日確認**: 山と予定日を登録し、前日に気象情報、オフラインパック、日没、アクセスの確認を促す。通知は端末内のローカル通知とし、既定OFF、初期時刻は前日18時、ユーザーが最初に有効化した時だけ権限を求める。通知は最新気象や配信時刻を保証せず、安全警報には使わない。
- **お気に入り山の更新表示**: お気に入りの山について、前回閲覧以降に気象、オフラインパック、公式情報の確認日等が更新された場合に一覧で示す。
- **気象の共有キャッシュ**: 複数ユーザー対応時はWeatherKit REST APIの秘密鍵をサーバー側だけに置き、閲覧された山をオンデマンド取得して複数端末で共有する。正式対応山域だけを必要に応じて先行更新し、全国山頂索引の全件巡回は行わない。
- 登山予定日を指定した比較表示（複数日の気象・日照比較）。
- 出発時刻、移動時間、日没を踏まえた「確認タイムライン」。
- 各山の季節別チェックリストと装備メモ。
- 家族・同行者へ共有するための、確認済み項目のエクスポート。
- Apple Watch での重要情報の簡易表示。
- 公式情報の更新検知、保存した山の情報更新通知。
- ユーザーによる情報修正提案。ただし公開・共有は運営側の確認フローを設ける。

## 13. 制約・リスクと対応方針

| リスク・制約 | 影響 | 対応方針 |
| --- | --- | --- |
| 山の見分け精度が地形・雲・磁気・GPS 精度に左右される | 誤った山情報の表示 | 常に候補として提示し、距離・方角・仰角・手動選択で確認可能にする。地形データの見通し判定を段階導入する。 |
| 山頂の気象は地域予報と大きく異なる場合がある | 安全判断を誤るおそれ | 対象地点・取得時刻・出典を表示し、公式気象情報への導線を設ける。 |
| 山小屋・交通・駐車場の情報は季節・臨時事情で変わる | 古い情報の表示 | 最終確認日または取得日時・公式リンクを必須化。承認済み情報源を低頻度で自動確認し、取得失敗や古い状態を明示する。 |
| 外部 API の料金・利用規約・停止 | 機能継続性・コスト | 提供元を抽象化し、代替可能な設計にする。個人利用MVPは端末キャッシュ、複数ユーザー対応時はオンデマンド共有キャッシュで重複呼出しを抑え、WeatherKitと配信基盤の使用量を別々に監視する。採用・移行前に規約を確認する。 |
| 電波不通 | 最新データを取得できない | オフラインパックとキャッシュ、最終取得時刻の表示。 |
| AI が不正確・断定的な表現をする | 安全面・信頼性 | 構造化データに限定、出典表示、断定禁止、重要項目の未確認表示。 |

## 14. 受け入れ条件

以下を満たしたとき、MVP の要求を受け入れる。

1. ユーザーは山名・別名・山域・都道府県・標高帯で検索・絞り込みし、任意の登録済み山の詳細を開ける。
2. カメラおよび位置情報を許可しない状態でも、一覧・検索・山詳細・個人メモを利用できる。
3. オフライン保存済み山域で通信を遮断し、位置情報・方位・端末姿勢を許可した状態では、カメラ画面に端末内データから算出した山候補を表示できる。
4. 山詳細には、少なくとも山名、標高、距離、方角、気象、日の出・日の入り、メモ、公式リンクが表示される。
5. 気象情報には対象地点、取得時刻、提供元が表示され、取得不能時はその状態が分かる。
6. 山小屋、登山口、駐車場、交通、温泉について、登録済み情報または公式参照リンクの少なくとも一方を表示できる。
7. ユーザーはメモとお気に入りを追加・編集・削除でき、アプリを再起動しても内容が保持される。AR候補を選択した後に限り、明示的な撮影・保存操作で「気になった山」の記録を作成・削除できる。候補を選択しただけでは写真も正確な位置も保存されず、視点位置は利用者が記録ごとに明示して有効化した場合だけ保存される。
8. 詳細オフラインパック未導入、通信なし、位置情報未許可のいずれでも、「今の時期の丹沢」が同梱データから表示される。位置情報を許可しても対応地域内に近い山がない場合は、その理由と山名検索の導線が表示され、遠い山を「近い山」として表示しない。
9. 通信を遮断した状態でも、事前に閲覧または保存した山の基本情報と個人メモを閲覧できる。最新でないデータには取得時刻が表示される。
10. 位置情報とカメラの権限・利用目的をユーザーが理解でき、不要な権限を拒否しても一覧・検索と保存済み情報の閲覧を利用できる。
11. カメラ候補表示では、位置・方位精度が低い場合にその状態を示し、ユーザーが手動検索・選択へ移れる。
12. 山詳細で前日の山頂付近の気象サマリーを現在・予報と区別して確認でき、未取得値を降水なし・降雪なしとして表示しない。
13. よく使う出発駅を1件登録・変更・削除でき、登山口アクセスから現在地または登録駅を選んで外部地図アプリを開ける。選択済みの目的地・移動手段を再入力せず、YamaLensの位置情報権限を拒否しても登録駅を利用できる。
14. 開発用ARテストパックを使用する場合、正式対応パックと区別でき、施設・気象・アクセス等の詳細情報が未整備であることを確認できる。
15. AR候補の現地評価には複数山域のログを利用でき、初期正式対応の完了判定には丹沢の代表地点を少なくとも1地点含む現地ログがある。
16. Debugビルドでは複数のARテストパックを一式として導入でき、カメラ候補を統合したまま、見通し判定と予測稜線に使うDEMを現在地の詳細地形範囲に応じて自動選択できる。範囲外のDEMを推測適用しない。
17. 検証済みYAMAP山ページが登録された山では、山詳細から対象山ページを開ける。YAMAP未導入時にも同じページをWebで開ける。

## 15. 実データ・実機で確認すること

1. 丹沢山地でMVPに登録する山・登山口・山小屋等のレコード一覧と、各一次情報URLを確定する。
2. WeatherKitが丹沢山頂座標で提供する雷・降雪・警報、前日のDaily Weather Summaryの各項目、予報品質、実機認証を確認する。
3. 国土地理院の採用データセットごとに、利用条件、加工表示、測量法上の手続を確認する。
4. 初期の候補算出パラメーターを固定リプレイと複数山域の現地ログで評価し、変更理由と回帰証拠を残す。初期正式対応の最終確認には丹沢の代表地点を少なくとも1地点含める。
5. `bootstrap.sqlite` と丹沢詳細パックを試作し、容量、読み込み時間、破損時のロールバックを確認する。
6. JR・私鉄・地下鉄を含む登録駅名をApple Maps／Google Mapsの出発地検索語として渡し、目的地までの経路を開けることを実機で確認する。
